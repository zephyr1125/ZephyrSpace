# 六家公司配对复核：校准批次协议

日期：2026-09-08。用户授权先做六家已有公司的三路复核。
样本在读取新审核意见前按行业及本地资料条件选定：伊利股份600887、美的集团000333、金山办公688111、招商银行600036、恒瑞医药600276、万华化学600309。
排除前次试点的西高院、Samsara、贵州茅台。本批用于校准，不计入下一批冻结验收。

## 固定条件

三路为两个无既往任务上下文的Codex子Agent与deepseek-v4-flash API。Flash使用非思考模式、每阶段12000输出token、不自动重试。
Codex继承当前模型配置，均执行相同覆盖要求；它们可用本地工具定位和重算，但不得联网或读取冻结包外的公司材料。
不把Codex完整agent工具运行与一次API调用视为完全相同计算预算，因此结果评价复核组合的实际表现，不推导纯模型能力排名。
相同公司、相同原始证据节选、相同当前初稿、相同规则、相同信息截止日。
证据准备员只选材，不给审核员提示已知错误；删去初稿中的历史修订/旧评分/旧审核意见，保留当前事实、计算与结论，不修正疑似错误。
保留原始源文件SHA256、节选行号与删减映射，冻结后不修改。缺失资料明确标出，不用初稿填充原始证据。

## 执行顺序

1. 六家材料与统一规则冻结，保存freeze.json校验值。
2. 每一路先读证据和规则，写第一阶段判断；写入后才能读取当前初稿，再写第二阶段问题。
3. 三路互不看输出。每家公司输出最多12个具体问题，正确性确认不计缺陷，疑似问题列unknowns。
4. 汇总每家公司全部第二阶段问题，移除作者标识、随机排序，生成匿名候选池。来源映射单独保存，裁决员不得读取。
5. 独立裁决员只看匿名候选池与冻结包，逐项给成立/部分成立/不成立/证据不足/非缺陷，按语义分组去重。
6. 先保存裁决再揭盲，统计双Codex并集、各单路、两种Codex+Flash组合的发现覆盖与误报。
7. 主Agent审查重大冲突与计算，记录任何改判理由；不按票数或模型名裁决。

匿名仅隐藏标签，文字风格可能泄露来源；主Agent知道执行来源，最终报告须披露这一限制。
对严重问题没有原始证据即不判成立。参考缺陷集合仅为三路提出后核实的并集，不是穷尽真值；“未新增漏P0”不能证明不存在其他遗漏。

## 指标与边界

- 各路：提出条数、成立的独立缺陷、部分成立、误报、不足证据及非缺陷确认。
- 保守纠错成立率：完全成立的具体纠错条目÷全部具体纠错主张（部分成立和证据不足也在分母）；纯建议/正确性确认不计分母。部分成立的认可部分可计覆盖，但不能当整条完全正确。
- 增量：Flash独有且成立的缺陷数及涉及公司数；与双Codex重合的问题单列。
- 组合：相对于已核实并集，各组合漏掉的P0/P1/P2；部分成立只按裁决认可部分计数。
- 运行：完成率、失败/重试、API输入输出token和耗时；Codex工具用时记录可得范围，不能只以API费用声称总成本更低。
- 第一阶段到第二阶段无解释改分/估值单列，不自动归入原稿缺陷。

本轮结束只给是否值得继续下一批的判断，不直接宣称“转正”。此前建议的≥95%运行完成率和≥80%纠错成立率需要更大样本，6家不适合强结论。
不修改三家公司或六家公司原研究、公司页、索引及Watchlist。确认的问题形成待修清单；本试验成功不表示旧研究已修复通过。
