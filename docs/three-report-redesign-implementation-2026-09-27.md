## 已完成

1. SOP和五个角色配置改为首次联合审核评分与估值，研究批准后成文。修复额度从联合初审后开始；评分单审不能消耗联合额度，最多一次合并修复及一次有据例外。资料齐备任务保留60分钟试验目标，准备、等待及所有角色成本计入。
2. 新增triplet_research.py，复用现有底稿与事实JSON，不引入数据库或平行数值台账。支持联合送审机械检查、事实期别/单位/归属、分红归属年与支付年、派生计算重算、实际估值输入与事实数值绑定。模型经济依据必须出现，但是否充分仍由独立审核判断。
3. apply-delta保留旧评分接口；联合模式增加受原验收ID约束的估值字段、指定模型及桥/数值记录修复。禁止越界修改另一模型、任意JSON路径修改和重置修复计数。生成完整新底稿及差异，不手改构建稿。
4. 裁决与底稿冻结到新版本目录，current.json只作指针。构建使用明确版本；旧裁决及旧输入不能被状态更新覆盖。发布批准继续在构建及正文验收之后绑定manifest，不形成循环依赖。
5. 评分批准和估值批准有不同投影；估值参数单独变化不撤销未受影响评分。现阶段保守绑定全部有效证据与原规则，因此只要这些依赖变化就要求重新判断，尚未实现细粒度事实依赖图。
6. 关联的底稿、交付、收尾、证据和修复接口文档同步。原32项评分、模型组合、A2/A3历史范围、双路完整审核及150/150/100行要求保持不变。

## A/B失败后的预算控制修复

上述有限对照已因超预算停止，不能按“下一阶段尚未发生”继续自动派发。随后新增 `scripts/triplet_budget.py`，执行规范见[预算控制](three-report-budget-control.md)：唯一配置哈希、启动前预留、未校准单角色串行、根任务与子任务实际计量、组合预算、在途及收尾余量、未知/过期计量停止、停止后结算但不抹去已用量。SOP已要求先reserve再派发，随后bind和持续watch，告警立即调用Agent中断工具。

新增9项本地回归，包括并发预留拒绝、配置变更拒绝、在途提前线、组合及总余额不足、根任务预算、缺失/过期/回退日志、缓存不重复计费、CLI非零停止和禁止初始化重置，以及运行中追加日志触发watch提前返回。全部通过；未启动任何新模型审核来测此功能。

历史只读回放见 `data/reviews/joint-review-ab-2026-09-27/final/budget-control-replay.json`：上次第一个审核启动前，根任务已用39,210，新配置会拒绝启动。三角色最大单次快照跃升42,156，示例将每个在途余量上取50,000；不是未来上界保证。回放没有实际中断Agent，不能推算精确反事实节省金额。

当前接口无法提供平台侧硬token封顶，脚本仅返回中断清单，主任务必须执行中断；日志延迟和在途生成仍可超支。此修复证明预算准入与提前告警可工作，不证明30%真实降耗、审核质量不劣或完整交付已达标。目标版B仍未启用。
