## 使用范围

跨模型复核先作为试点。每家公司保留 Codex 事实核查员；DeepSeek 承担逻辑审查。
两路可以并行，互不阅读对方意见。主 Agent 统一裁决，不能取平均分或按多数票判断。
没有密钥或 API 失败时，执行原有两名 Codex 子 Agent 的逻辑/事实复核，并记录外部复核未完成。
不允许把材料准备成功、空响应、截断响应或只有第一阶段成功记作跨模型复核完成。

## 准备证据包

在 `data/reviews/公司代码/manifest.json` 创建显式清单，例如：

```json
{
  "id": "688334",
  "company": "西高院",
  "cutoff": "2026-09-08",
  "rules": ["data/reviews/688334/rules.md"],
  "evidence": ["财报/西高院/西高院2026年半年度报告.md"],
  "drafts": [
    "深度分析/西高院 深度分析 73 2026-09-07.md",
    "管理层档案/西高院 管理层档案 72 2026-09-07.md",
    "估值分析/西高院 估值分析 2026-09-07.md"
  ]
}
```

示例只演示路径结构，实际证据应覆盖至少三年经营数据、最新报告、治理、股本、估值输入和反证材料。
`rules.md` 只包含本次适用的评分维度、硬门槛、行业模型规则和统一买入价公式。
不要直接传整个 Skill：其中的案例、历史评分、执行指令会污染盲审。
证据包应包含原文、出处、日期和取数口径。不得用初稿摘要代替证据。
第一阶段隐藏作者总分、目标价、结论和带评分的报告文件名；脚本隔离 drafts，主 Agent 仍需检查 rules/evidence 是否夹带这些信息。
路径限定 Vault 内的文本文件，PDF 应使用已归档转换稿。脚本拒绝疑似密钥、隐藏文件、越界路径和超预算材料。
字符上限是本地预算控制，不是精确 token 计数。超过模型上下文仍可能由 API 拒绝，不得静默截断。

## 执行

在本地被 Git 忽略的 `.env` 设置 `DEEPSEEK_API_KEY`，也兼容 `DEEPSEEK_KEY`。
密钥不要写入材料清单、报告或命令行。所选材料将发送至 DeepSeek 官方 API，计入其账户用量。

```powershell
# 只准备材料，不调用 API。
python scripts/deepseek_review.py --manifest data/reviews/688334/manifest.json
# 执行两阶段复核。
python scripts/deepseek_review.py --manifest data/reviews/688334/manifest.json --execute
```

依赖现有环境中的 `requests`、`python-dotenv`。默认模型为 `deepseek-v4-pro`，可用 `--model` 显式指定。
每阶段默认最多 12000 输出 token；`--max-tokens` 可调整，过小导致截断时记为失败。
默认请求读取超时为 300 秒，不自动重试，防止不确定结果重复计费。
每次新建 UTC 时间戳目录，不覆盖历史结果；保存材料 SHA256、行号、两阶段请求、结构化意见、模型、用量、耗时和状态。
脚本不提供联网工具；DeepSeek 提到的新增事实和链接均须由 Codex 另行核验。

## 裁决与回写

Codex 事实核查员应直接读取最新官方来源，重算评分与估值，不能只核对 DeepSeek 的说法。
主 Agent 在运行目录新建 `adjudication.md`，逐项记录：问题、两路意见、原始证据、采纳/驳回/待核、理由、评分及估值影响。
P0 修复后重跑受影响复核；P1 修复后检查公司评分、管理层评分、目标价、买入价和档位联动。
报告按 Vault 版本规则新建，保留旧版；公司页和索引切换到最新版本。
只有三件套、公司页、索引和自检完成后，主 Agent 才能按既有规则更新、验证及同步 Watchlist。
外部复核结果不能直接写入 Watchlist，也不能自动当成已核实事实。
