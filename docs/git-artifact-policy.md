# Git 研究产物管理规范

Git 保存长期知识、可复核结论与可维护源码；过程缓存留在本地。忽略不等于删除或备份，也不会缩减既有 Git 历史。

## 保留版本管理

- 公司页、索引、专题、日报、正式及历史三件套报告。
- `财报/` 中的原件、转换稿、图片及 MinerU 辅助归档；沿用 `_Inbox/` 临时入口例外，不全局忽略 PDF、图片或 JSON。
- `data/research/` 的证据、参数、计算脚本及自检，可能是报告的唯一复核依据，不整体忽略。
- `data/reviews/` 的共享证据、来源索引、计算底稿、结构化审核问题、修复说明、最终裁决及收尾结论。保留文件不代表研究通过验收。
- Watchlist、规则配置、源码、测试、评估基准和有意留存的评估结果、`.codex/agents/` 角色配置。
- 新装配流程的bundle、有效证据/底稿/裁决、三份source源稿保留；source是长期可再生产物，不是writer临时草稿。build-v*/及build-final/中的生成副本留本地。最终使用`triplet_delivery.py archive-release`保存到`final/release-版本/`：保留获批manifest、裁决、递归复核引用和全部直接输入的字节快照，正式报告映射写入release.json。公司页链接此验收包，不链接被忽略的构建或审核工作目录。
- 独立评分阶段可保留`final/评分结论.md`及`final/score-package.json`，明确尚未完成完整三件套。清单绑定获批底稿、原规则、证据及两路复核/裁决的哈希，必要输入快照放`final/inputs/`；不得只链接被忽略的角色目录，也不将该包冒充完整报告release。

## 本地保留、Git 忽略

- 审核运行目录中的角色工作目录、匿名副本、冻结副本、历史报告复制件和 `drafts/`。
- 作者 `writer/` 目录历史上混有唯一计算底稿，当前只忽略其中 Markdown 草稿，保留计算脚本、参数和源文提取；新任务按上述目录分工存放。
- `draft-*`、`*-draft.*` 草稿，以及模型请求、原始响应、重复输入、运行状态和耗时流水；匹配限定在 `data/reviews/` 内。
- `data/reviews/process-audit-*/` 本地任务统计；长期复盘结论放在 `docs/`。
- `data/reviews/**/schema-replay/` 为可重建的装配回归副本，留本地；测试结论及必要失败证据写入非忽略的验收记录。
- `data/reviews/*forward-test*/` 工具前向测试副本，以及各run生成的`score-rules.md`/`valuation-rules.md`原文阅读包留本地；程序、原规则和验收摘要入Git。真实研究的获批输入快照仍按评分归档要求保留。
- `triplet-token-cycle-*/round-*/`的角色工作副本忽略，包括writer/evidence、拆分的numeric/external以及repair-sol/rebuilt-sol；可再生的source-views也忽略。每轮结束先把评价所依据的完整冻结输入和两路审核复制到final并记录哈希，成功与失败都留评价，禁止仅保留“测试通过”文字。
- API 用量流水、筛选过程数据、财报预告抓取快照，以及明确命名的脚本扫描缓存、批次 staging 和链接检查输出。
- 有限审核对照 `joint-review-ab-*` 保留冻结候选、原规则摘录、留出材料、预登记预期、清单及final结果；由本地原件生成的original文本视图和outputs工作目录忽略，必要部分审核复制到final并明确未完成。原件位置和字节哈希仍保留，不把失败试验标成通过。
- 研究目录顶层的 ZIP 打包副本、`runtime-checkpoint-*` 阶段计量、首次超限及评分冻结计量留本地；终局 `run-audit.json` / `final/runtime-audit.json` 和验收快照继续保留。本次提交整理不整体解除历史目录追踪，避免切断旧报告的唯一复核引用。
- 现有缓存、日志、环境密钥及编辑器临时文件规则继续生效。

## 新研究落盘要求

1. 初稿、修订稿、审核工作副本统一放入 `data/reviews/<run-id>/drafts/` 或角色目录，禁止把重复工作副本散落到正式报告目录。
2. 验收后再发布正式报告。明确标注的未完成结论可以留档；不按“修订版”“未完成”等关键词批量忽略，避免隐藏历史记录。
3. **唯一证据和最终底稿不得只存在于被忽略的目录。** 收尾时把必要来源索引、数据定位、参数、重算脚本、计算结果、最终审核问题及处置复制到该 run 非忽略目录（如 `evidence/`、`final/`），修正正式文档链接；不复制整套工作目录。
4. 冻结稿仍可用于本地复核；长期复核所需事实和公式应在正式报告、财报归档或保留底稿中可定位。
5. 筛选缓存若成为正式结论唯一依据，将必要快照归档到 `data/research/<公司>/<日期>/`。
6. 历史工作目录内若混有唯一计算底稿，解除跟踪前先保留底稿。只从 Git 索引移除明确的过程文件，不删除磁盘文件，不清空索引重加全库，不改写历史。

终局 `final/inputs/` 和 `final-terminal/inputs/` 的验收快照显式保留，包括沿用原目录结构的旧快照，避免其中的 writer Markdown 或评分规则包被工作副本忽略模式误排除；仅将清单绑定的必要输入放入这些目录。

## 验证

用 `git check-ignore -v --no-index <路径>` 检查命中规则。正式报告、财报、裁决、底稿及源码应不匹配。`git ls-files -ci --exclude-standard` 可列出已跟踪的忽略文件，须逐项分类，不能直接全库解除跟踪。

2026-09-27茅台接口试验的author工作目录已将最后原始底稿、事实、来源和索引按字节归档到final/inputs，并保留stopped-snapshot及失败检查，因此工作目录只在本地保留。闭卷估值试验的input.json属于不可缺少的固定基准，显式解除通用请求缓存忽略；其原始和修订输出用于复现已发现错误，不按通过样本筛选删除。此处不批量忽略其他author目录，避免隐藏唯一研究证据。

## 2026-10-25 公开同步范围（优先于上述历史 Git 归档约定）

本仓库为公开仓库。按用户本次明确要求，Git 仅同步经审查适合公开的正式及历史三件套、公司页、相关导航与主题、必要公开配置，以及单独审查的可维护源码。上方关于财报原件、研究过程证据及输入快照进入 Git 的旧约定不再用于公开同步；其本地归档要求继续有效。

- 财报原件、转换全文、图片、MinerU 产物、转载剪藏、研究输入与输出、模型请求响应、缓存、运行流水、导出包及本地工具状态均留本机。
- 私人持仓、股数、市值、账户信息、调仓方案及其衍生研究不公开；个人观察目录默认留本机。环境变量、凭据、密钥不得公开。
- `data/` 通过 `.gitignore` 明确保留 Watchlist 研究配置、schema、规则、来源配置和新闻分类配置。它们是研究名单，不应加入个人持仓字段；每次发布仍须检查具体内容。其他数据默认本地保留，不能整体删除。
- 本次不公开过程验收包或结构化摘要：其中可能夹带原文、个人数据或冻结输入。未来若确需公开最小验收摘要，应单独审查内容并精确增加白名单，禁止直接解除整个研究目录的忽略。
- 正式报告和公司页继续保留原有本地证据链接。链接到 `财报/`、`data/research/`、`data/reviews/` 等本地材料的引用在云端副本不可访问；这不代表证据已删除，也不代表云端副本包含完整复核材料。外部官方公开链接和正文可继续阅读。不得为消除云端断链而改写研究结论或自动上传原文。
- 对已跟踪且现在应忽略的材料，仅取消 Git 索引跟踪，逐项确认磁盘文件仍存在。禁止删除工作区材料、清空索引重加全库或重写历史。停止跟踪不会清除已经公开的历史对象。
- 按需同步时，先看 `git status`，按明确路径选择报告与必要配置，再审查暂存差异、敏感信息和引用影响；不得盲目 `git add -A`。其他正在进行的源码、规则或研究改动留待各自任务提交。
- 提交前确认忽略样本命中、正式报告不命中，并扫描全部新增或修改的暂存内容及将推送的新提交；有未知内容或有效密钥时停止公开传输。正常提交后只做非强制推送，并核对远端分支的 commit ID。不启用自动定时推送。
