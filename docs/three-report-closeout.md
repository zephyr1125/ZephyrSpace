# 三件套评分展示与结论收尾

本文件定义决策、状态和验收边界。模型、角色、轮次和交接只在 [调度SOP](three-report-economy-routing.md) 维护；底稿字段及差异检查只在 [底稿规范](three-report-workpaper.md) 维护。

## 整数总分显示

2026-09-20起新研究：公司总分、管理层总分及合计分在最终回复、报告摘要/元数据、文件名、公司页和索引中用整数，采用四舍五入（ROUND_HALF_UP，非Python银行家舍入）。合计先加原始总分再舍入，不加两个已舍入显示值。评分变化从原始差值计算后显示；若小于一分则写“未满一分”，不伪装成完全无变化。

分项、底稿、裁决与Watchlist机器字段保留原始分；评分规则、半分调整及所有资格/红线/评级门槛使用原始分。显示达到门槛而原始分未达到时，明确写“显示值经舍入，原始评分未达门槛”，不因显示整数入池。未知仍为null，不能显示0。估值价格、确定性、财务比率不属于此次整数显示变更。历史报告及已冻结底稿不追改。

`workpaper` 的原始 `scores.*.total` 不变；新底稿声明 `score_display: "integer_half_up"`，生成器据此输出整数总分标记，旧底稿缺此字段继续旧格式。分析判断必须逐项有依据，不能为了凑显示分调整分项。

## 明确决策，独立记录研究状态

| decision | 使用条件 |
|---|---|
| eligible | 完整研究、双复核与裁决验收通过，达到现行最高合格档，无红线 |
| reject | 已核红线或可信评分/有据边界足以否决全部收录档；写明规则与证据 |
| defer | 不确定性影响资格，或执行未完成；写决定性原因、仍可信内容和重评/恢复条件 |

| research_status | 含义 |
|---|---|
| verified_complete | 完整研究验收通过 |
| closed_with_uncertainty | 可得证据已评估，错误已纠正或全部依赖结论撤回，剩余未知有清楚边界；不等于完成正式定价 |
| execution_incomplete | 仍有已知错误、遗漏或验收未执行；不得当作企业不合格 |
| gate_excluded | 依原有准入规则压缩退出，不称完成双复核三件套 |

每次都有明确处置；不能仅写“无法闭合”。技术中断须列完成阶段、无效字段及恢复点。轮次耗尽、程序通过或decision有值都不等于研究通过。

## 证据、评分与预测的边界

- 已公开但未取得：定向补证并核官方原件；同源反复失败按证据规范换源，不能称公司未披露。
- 未公开且无法可靠推导：标未知。能给有据上下界时展示决策影响；没有合理边界不填任意点值。
- 未来经营参数：有经营/历史/可比依据的假设，提供情景与敏感性，不要求证成已发生事实；不允许用假设掩盖账面口径冲突。
- 评分：作者依事实和规则作分析判断，审核核匹配性，裁决选择或修正；不要求公司公布分数，不把“综合判断待复查”长期当缺证。保留已验收分项，不因一个模型失败抹掉全部事实或重复扣分。
- 分数区间只在上下限均有依据时使用；不取中点充当正式分。只有上下界给出同一资格结果才可明确裁定；跨门槛则暂缓。Watchlist不填未知分数，不新增评分/估值门槛。

作者展开全文前，在原底稿中确认关键模型输入、预测依据及不可替代缺口，不另设审批。只有一个可靠模型时不得强凑第二个或以降低确定性代替验收；对仍可能合格的公司，缺独立模型就明确估值未完成。

## P0/P1的最小充分验收

每项列错误/缺口、影响字段或决策、原件定位和最小验收条件。事实、单位、归属、现金双计、股数时点或模型错误，必须改正或撤回全部依赖结论；改叫“诊断”不能保留错误价格。合理预测分歧不自动升级P1。

已给正确金额、可直接复算且不影响判断的展示缺项是P2；只有掩盖事实或改变评分/估值时才升级。未披露人事动机如实标未知并删除依赖褒贬，不要求凭空补齐；公开公告可得而漏查仍是执行缺口。裁决后不因个人偏好新增条件，重大新错按SOP例外处理。

修复从冻结版本复制后打补丁，沿事实→评分/模型→表格→正文/公司页传播，保留无关已核内容。逐验收ID给位置与证据，禁止循环引用“见最终稿”；作者声明由双路定向复查验证。最后验收分歧按SOP终局，仅依冻结材料区分错误、不可知、合理判断与展示问题。

## 质量不达标与停止定价

可信评分或已核红线已否决全部档位时，按 `data/WATCHLIST_RULES.md` 给reject/NONE，不因估值未批准又改成defer。NONE可停止正式估值：目标价、确定性、买入价均为null，撤掉错误诊断价格及价格区；保留完整研究、适用方法、停止理由、经营情景和重评条件，明确未完成正式定价。该出口不适用于评分未完成或合格候选的模型缺失。

## 发布检查与最终记录

正文、评分表、元数据、底稿、公司页和索引须对应同一套裁决参数、显示规则和状态。已批准评分不残留“null/待复查”，事实纠正落实到新稿；旧冻结稿保留，历史数值明确标历史。双路验收通过后才把送审标签切换成已验收，不能仅靠终局JSON隔离仍冒充有效结论的旧正文。

`decision-closeout.json`至少包含 `decision/research_status/answer/approved_parameters/withdrawn_fields/verified_findings/blocking_items/review_refs/next_trigger`。blocking_item列 `id/category/impact/disposition/source_ref`：category取fact_error/model_error/evidence_gap/irreducible_uncertainty/presentation；disposition取corrected/withdrawn/bounded/open。参数逐字段区分已批准值与null；候选不占“最终价格”位置。

最终反馈给处置答案、公司/管理层/估值各自状态、原因与重评条件；整套更新补SOP要求的前后对照。不追溯把历史未完成任务说成通过，不推翻用户暂停决定。
