# 三件套简化分析

触发口令：`三件套简化分析XXX`，例如“三件套简化分析耐克”或“三件套简化分析 BOOT”。通过现有company-triplet入口调用；普通“三件套分析”仍使用经济组合SOP。本文件是简化模式调度真源，优先于通用文档中的双审、强制裁决、JSON先行和装配流程要求。

## 角色与工作顺序

优先执行[单项低分强制退出](three-report-closeout.md#质量不达标与停止定价)：作者先评分，任一原始分<70立即暂停估值，仅核验低分依据；独立审核确认后停止后续分析并低分登记。下文“三份完整报告”、估值及篇幅要求仅适用于未触发退出的任务，不得先做完估值再判断是否入池。

1. 主任务推荐使用`gpt-6.1-sol / low`，由用户在会话界面选择；本SOP不自动切换主任务模型。主任务固定公司、市场、资料截止日和新产物目录。未指定截止日时采用本次日期，并核实当时已披露资料；不沿用Boot Barn案例的截止日、价格或额度。复用历史批准前核版本、适用事实及变化，不直接继承旧估值。
2. 一位作者使用`gpt-6-astra / low`，从原件形成可读研究底稿、可复算计算和三份完整报告草稿。事实、反证、选档理由及未知影响必须清楚；不先要求填写整套生产JSON。已有计算工具可复用，不为格式阻碍开发工具。
3. 一位独立完整审核者使用`gpt-6.1-sol / low`，一次检查三份全文、全部评分、关键估值依据及决定性原件，集中列齐重大问题与最小验收条件。证据缺口先按下文“证据缺口的实质性判断”核验影响，再决定是否阻塞。作者自检不代替审核；允许合理判断和真实未知，不把未知编成负面结论或伪精确区间。
4. 作者最多一次定向修正，原审核者仅验收问题及改动引入的重大错误。仍有真正判断争议时才由独立的`gpt-6-astra / low`裁决者核原件裁决；不借裁决追加研究或修复循环。无争议不启动裁决。
5. 获批后由主任务核报告、计算及验收哈希，按获批字节新建正式报告，回写公司页与索引；符合既有入池规则时串行更新Watchlist，验证后同步。历史版本保留。未通过则保留已批准部分，明确未决问题、影响及所需人工判断，不宣称完整成功，不写入未获批参数。

用通用`worker`/`default`子代理显式指定上述模型与强度，`fork_turns="none"`，交接职责、必要路径及当前范围；不套用绑定旧双审/JSON流程的自定义角色指令，不修改普通角色TOML。模型不可用时说明阻断，不静默替换。子代理不得再派角色，不写公司页、索引或Watchlist。没有必要不单独启动证据代理，不启动第二审核者或救火作者。

## 不变的质量与交付要求

- 沿用32项分项结构、公司/管理层/估值内容及适用行业约束，评分采用当前内容模块规则：读取`deep-prebuy-skill/SKILL.md`、`management-archive/SKILL.md`（含review-checks）、`skills/valuation/SKILL.md`的内容规则和适用附件。其中调度及交付步骤以本文件为准；真实未知不得任意扣分。
- 原件与期别核验按[证据规范](three-report-evidence-contract.md)；历史范围及阻塞标准按其“历史核验与实质性验收”执行，A2采用质量模块现行评分口径。共用证据就近引用，局部读取，避免重复倾倒全文。新建研究须覆盖必要历史；更新须覆盖新增财报及截止日之间的重大事件。
- 仍须提供适合行业的估值依据、三情景、敏感性、交叉验证及统一买价公式。现金流期间、估值时点、折现、股数与单位一致。最终总分显示整数，分项及门槛保留原始分。
- 三报告保留项目要求的完整内容及150/150/100行下限，不以摘要冒充报告。正文不留占位和过程指令。保存草稿不等于批准；未取得、无法推导、不适用及撤回可正常表达。
- 保留审核记录、获批报告与底稿哈希、来源定位、版本及有效链接；可以像已验证的恢复样本一样直接按获批字节归档，不要求通过仅支持双审核的装配器，不伪造第二路记录。获批后正文有实质变化须验收受影响部分，不能自行改结论。
- 公司页及入池沿用`docs/three-report-company-page.md`、`data/WATCHLIST_RULES.md`和`data/watchlist_meta.json`。报告及验收记录注明采用单独立审核；减少冗余可能增加漏检风险，未证明与双审等效。

## 证据缺口的实质性判断

沿用[评分与收尾规范](three-report-closeout.md#证据评分与预测的边界)的充分证据和可辩护判断原则。证据缺口先评估对评分、入池门槛和估值的影响，不以资料是否齐全直接决定整个流程能否继续。

- **作者先评估影响，审核者独立核验。** 在现有底稿中说明缺什么、已查范围、涉及的分项及模型输入，以及合理不同结果是否会改变评分选档、入池资格、重大红线或估值结论。结合业务性质、收入利润量级、资本投入、合同责任、核心战略依赖及治理风险判断；可定量时给量级或敏感性，无法可靠量化时说明依据与边界，不虚构金额、上限或概率。缺少金额不自动等于重大，也不自动等于不重大。
- **非重大未知披露后继续。** 证据足以支持原规则选档和核心结论、缺口不构成实质影响时，保留未知、判断理由和重评触发条件，经独立审核接受后继续评分、估值及完整交付。不得因单个次要项目结果不明、缺少全套内部KPI或重复旁证阻塞整套流程；不把未知改写为成功、失败、零风险或默认中档分。
- **D2逐项核验与年度归并分开。** 保留连续年度窗口、逐项目标结果、期限及原规划修订记录；年度达标按有证据支持的核心经营与战略目标综合判断，说明重要性依据。不得擅加“任一单项未知即全年不能达标”的一票否决条件，也不得仅挑成功项目或删除重要失败来提高达标率。次要项目未知可与核心年度目标达标并存；明确期限本身不使项目自动成为决定性事项，年度达标也不等于全部承诺兑现。评分仍使用既有档位，不改分母凑分、不插值过关。
- **实质缺口仍阻塞受影响结论。** 若合理不同结果可能改变分项选档、资格门槛、重大红线或关键估值依据，且现有证据不能支持有理由的判断，须明确具体影响、原件定位和最小补证条件，定向补证或保留相应结论未决。重大赔偿、出资/担保义务、虚假披露及核心项目持续失约不能因已实现收入小而忽略；已核事实错误和模型错误仍须纠正。不得用降低估值确定性替代必要核验。
- **保持有界交付。** 实质性评估写入现有底稿与审核记录，不增设代理、审批或补证循环。保留已批准部分；只有受影响结论妨碍资格或完整交付时才阻塞整套，完整验收前仍不得更新Watchlist。新规则不追溯改写历史报告、评分和审核结论。

## 停止边界

本口令只授权研究，不开展工程优化、审核A/B、新工具开发或额外验证项目。以一小时内获得完整结论为目标，不保证冷启动速度，不以时间压力降低质量；失败按上述出口给出明确结果，不自动追加循环。

预算仅采用本次用户授权，不继承历史“额外5%/10%”。有明确上限时计入准备、主任务、所有角色、失败及收尾，预留余量，到限停止；额度仅能近似观测时如实说明，不以内部token估算冒充平台额度。不自动提交推送。
