# 三件套预算准入与提前停止

预算控制由主任务负责。新有限试验必须先建立本页配置；预算不足则缩小**明确的试验范围**或报告无法容纳，不能偷减正式研究质量。提示词额度、静态分词量和事后统计都不能替代准入。本工具不改变模型、评分或审核要求。

## 单一配置

每次任务在run内保存一次budget-config.json，创建预算状态后禁止修改上限。示意配置（会话、日志和起点须替换为真实值，额度根据任务另定，不能当作已授权新试验）：

```json
{
  "schema_version": 1,
  "root_thread_id": "实际根任务ID",
  "root_log": "本机实际根会话jsonl绝对路径",
  "since": "2026-09-27T11:48:13Z",
  "total_limit": 200000,
  "coordinator_limit": 70000,
  "closeout_reserve": 30000,
  "inflight_reserve": 50000,
  "max_active": 1,
  "stale_seconds": 30,
  "roles": {"terra": 85000, "sol_full": 85000, "sol_focused": 85000},
  "groups": {
    "A": {"roles": ["terra", "sol_full"], "limit": 90000},
    "B": {"roles": ["terra", "sol_focused"], "limit": 90000}
  }
}
```

角色limit是最大可预留额度，不等于允许直接花完。上次日志的最大单次计数跃升为42,156，本例将每个在途余量上取50,000；角色在3.5万前后要求停止（8.5万减5万），协调在2万要求停止扩展。未来单次仍可能超过该余量，须持续校准。closeout_reserve独立留给最终记录和回复，不作为额外可用额度。groups把共用Terra分别纳入两配置，但实验总量只计一次。示例允许第一位审核后发现余量不够而拒绝启动第二位；它**不保证20万能完成这项试验**。

since必须是本次准备开始时间，不能填首次分派时间以隐去准备成本。继续旧会话按起点累计快照作差。日志缺失、计数回退、过期或缺起点时停止，不能填零。

## 主任务执行顺序

```powershell
python -X utf8 scripts/triplet_budget.py <配置> <budget-state.json> init
python -X utf8 scripts/triplet_budget.py <配置> <budget-state.json> reserve terra
```

只有reserve返回reserved才可派发该角色。提示词直接沿用输出的limit、stop_line和配置哈希，不手写另一份额度。先完成首位审核与结算，再决定下一位；未校准时max_active=1。已有预留即占并发槽，不能先启动多位再登记。

启动后立即绑定实际会话ID与日志：

```powershell
python -X utf8 scripts/triplet_budget.py <配置> <budget-state.json> bind terra <会话ID> <日志绝对路径> --wait-for-first-sample 20
python -X utf8 scripts/triplet_budget.py <配置> <budget-state.json> watch --seconds 40 --compact
```

watch每秒读取日志，达到提前停止线就立即返回，不等满30秒。主任务在审核运行期间持续接续watch，**不能先做长篇分析或其他大输出，之后才想起检查预算**。单次最多60秒；进度沟通后立即继续。bind可用--wait-for-first-sample 20（0至30秒，缺省0保持旧行为）处理刚启动时首个可信快照延迟：先保存绑定，只在唯一问题是首次快照尚未到达时原地短等，不报告ready或把该角色当零消耗，也不派发别的角色。身份错误、日志缺失、其他未知或任何已知预算停止立即返回；超时仍stop_required，主任务中断后按原谱系处理。它不放宽预留、在途或总上限。

返回stop_required或命令非零退出时：主任务立即对interrupt_thread_ids执行 `collaboration.interrupt_agent`，核实已停止，再读取已有产物。禁止先发送“请写完总结”继续生成；禁止再启动替补或改名清零。无法读取状态时，按已知调度清单中断本次全部活动子任务。中断失败时重查同一任务句柄，不能假装停止。

有权威完成/中断结果后才能结算：

```powershell
python -X utf8 scripts/triplet_budget.py <配置> <budget-state.json> finish terra --confirmed-stopped
```

finish只释放未使用预留和并发槽，已经消耗的token永久留在本次总账；之后仍会读取其日志，计入迟到计数。不能通过finish把活跃任务假装结束。配置、状态仅由主任务串行写入；脚本用锁及原子替换防止竞争覆盖，同一角色不能重复预留或换会话重算。

若分派工具明确返回未启动，主任务可用 `cancel <角色> --confirmed-not-started` 取消预留；不能用于已启动或启动状态未知的会话。取消仍保留记录，不能把同一角色名重新预留来伪装另一轮。

## 限制与实际修复范围

### 同会话恢复与闲余额度调配

有权威停止结果并执行finish后，可用 `resume <角色> --confirmed-stopped` 再准入同一会话；返回resume_reserved后才调用followup_task。它保留会话、日志、起点及全部累计消耗，重新检查角色、组合、并发与总预留。仅给已存在可信计数的旧会话一个stale_seconds恢复窗口等待新快照，超时仍停止；缺日志/缺计数不会获准恢复。恢复不增加研究修复轮次。

若角色分配过紧，全部角色停止结算后可执行 `transfer <已完成供方> <既有受方或coordinator> <整数额度> --reason <具体原因>`。仅转移供方未消耗额度，不改变配置、总上限、收尾或在途余量。已获授权的例外接手可用 `allocate <已完成供方> <新接手角色> <额度> --reason <裁决及接手原因>` 从原预留划出额度，原角色及其花费继续计入；不得以此增加研究轮次。组合内供方禁止向新角色或coordinator转出，以免绕过组合上限。

对尚未启动且从未预留的原角色，可给transfer加`--confirmed-not-started`调出计划额度；主任务须确认未派发，供方仍保留大于在途余量的上限，未来照常准入。已有状态的角色不能冒充未启动。只允许通过原额调配解除受方提前线；未知计量、其他角色停止或总预算停止不能放行，调配后必须重新检查通过。总上限、角色额度总和（含协调转入）、历史费用和收尾余量均不增加。

调配保存在transfers，恢复保存在resumes，最终须一并归档。`metering-timeout <1至300秒> --reason <延迟实测依据>` 仅在全部角色停止后校准子角色计量等待，记录历史，不修改token停止线或主任务等待。60秒快照无更新不必然表示异常；本次实跑出现正常步骤延迟，校准到300秒后裁决完成。仍不可将缺日志/未知计数当零，超过窗口继续中断。以上命令不是追加研究授权，只用于已授权的剩余工作。

脚本能拒绝无余额/并发超限的预留、校验身份与配置哈希、监测实际非缓存输入＋输出并返回中断清单。它不能直接调用Codex Agent中断工具，也不能控制平台每次生成的硬token上限。主任务仍须执行中断；日志延迟或单次在途消耗超过余量仍可能导致超支，超支必须如实报告。因此这是**提前控制，不是平台硬限额保证**。

只有减少无效读取、重复交接和模型调用才能真正降耗。预算控制修复的是及时停止和不再叠加任务，不能把未完成研究变成高质量结论。质量、完成率、时间及token分别验收。

配置/最终预算报告属于复核依据；budget-state.json及锁、临时写入文件是本地过程状态。根任务与子任务的用量均计入；审计后继续收尾的消耗须另计或明确快照下界。不得以已经有报告文件推断Agent已停止。

## 降低监控本身的上下文开销

运行中用`watch --seconds 40 --compact`，保留状态、累计量、各角色用量、全部停止原因及中断ID；需要审计详情时才用check。精简输出不改变停止规则、异常处理或退出码。不要每次重复返回缓存量、全部时间戳和固定说明。

Codex工具调用可在一次functions.exec内等待同一个watch进程，避免每十秒回到模型轮询；外层yield_time_ms设55000，exec_command先等30000，若返回session_id则用write_stdin等15000。若仍有session_id或外层返回运行cell，继续等待原句柄，不能重开进程。每轮总等待保持60秒以内，停止信号一到立即处理；不能把循环包装成长时间失去监控的后台任务。
