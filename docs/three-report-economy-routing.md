# 三件套经济组合调度

完整新建、整套更新及修复的唯一调度真源。用户说“三件套分析XXX”等即使用本组合，不重复询问；用户明确指定的组合优先。局部请求保持原范围。目标是在60分钟内先交有证据支撑、经过独立双复核的最终公司分和管理层分；在质量约束下减少token。不以无得分的defer或单元测试通过冒充达标。估值和长篇交付单独记录状态，不阻塞已有依据的评分批准。

## 规则归属与读取

同一规则只在所属文件维护；已读且未变内容在同一角色上下文复用。主任务交接给路径、版本、范围和验收条件，不转贴全文。

| 规则 | 唯一位置 | 读取者 |
|---|---|---|
| 模型、阶段、隔离、交付 | 本文件 | 主任务全文；各角色读职责及当前阶段 |
| 原件、期别、数据源、独立核验 | [证据规范](three-report-evidence-contract.md) | 全部角色 |
| 公司/管理层/估值内容 | `deep-prebuy-skill/SKILL.md`、`management-archive/SKILL.md`、`skills/valuation/SKILL.md` | 作者和双复核读核心及触发附件；裁决按争议定位 |
| 评分/估值计算、审核JSON | [底稿规范](three-report-workpaper.md) | 作者读作者/修复；审核读审核输出；裁决读裁决格式；主任务读交接命令 |
| 交付装配、引用、交付补丁 | [交付规范](three-report-delivery.md) | 主任务及作者；审核/裁决读问题分流 |
| 分数展示、决策状态、异常验收 | [收尾规范](three-report-closeout.md) | 作者、复核、裁决、主任务；证据角色不读评价材料 |
| 公司页、市场风险、发布 | [公司页规范](three-report-company-page.md) | 主任务；作者按市场承接内容 |
| 入池、字段、同步 | `data/WATCHLIST_RULES.md`、`data/watchlist_meta.json` | 主任务回写前；作者/审核核资格时读取门槛 |
| 草稿与证据留存 | [Git产物规范](git-artifact-policy.md) | 所有写文件的角色 |

证据角色只按缺口读数据获取附件，不读作者模板。历史案例、接口示例和行业附件按模块的明确触发条件加载；评分细则、适用行业约束、管理层review-checks不能跳过。A/H双重上市额外读 `docs/ah-share-selection.md`，统一选定市场与币种。

## 固定角色与权限

| 角色 | 模型 | 强度 | 职责 |
|---|---|---|---|
| triplet_evidence | gpt-5.6-terra | low | 中性证据、原件索引及缺口 |
| triplet_writer | gpt-5.6-terra | low | 三份报告、底稿和合并修复 |
| triplet_review_facts | gpt-5.6-terra | low | 独立全文复核，侧重原文与计算 |
| triplet_review_reasoning | gpt-5.6-sol | low | 独立全文复核，侧重模型、归因、反证 |
| triplet_adjudicator | gpt-6-astra | low | 匿名争议裁决、最终参数与验收条件 |

例外接手角色 `triplet_repair_writer` 使用 gpt-5.6-sol / low，仅在下述修复失败触发时启动，替代原作者执行剩余额度内的修复，不增加常驻角色。

角色配置在 `.codex/agents/`，须与上表一致；角色按职责命名，模型仅由配置指定。启动前核对工具加载的角色模型；若仍为旧配置，按下述显式配置方式启动。作者不得兼任审核；裁决不得兼任本轮作者或初审；两路重点不同不减少三份全文覆盖。所有子角色只写分配的产物，不递归启动Agent，不改历史/冻结稿、公司页、索引或Watchlist，不自行提交/推送。主任务仅调度、核交付、串行发布，不重复撰写研究。

优先按自定义角色启动。不可用但工具支持显式配置时，读取对应TOML并传入模型、推理强度和角色指令；`collaboration.spawn_agent` 使用 `reasoning_effort` 与 `fork_turns="none"`，不继承父任务整段历史。两种方式均不可用或运行时明确模型不符，则停止依赖该角色的环节并报告，不静默替换、不无限重试。禁止子Agent的任务不假装完成双复核。主对话模型由用户界面决定，本SOP不修改它。

## 阶段与交接

### 1. 固定范围与准入

主任务固定公司、市场、信息截止日、run目录及历史版本；入口检查命令在 `skills/company-triplet/SKILL.md`。仅新候选适用准入闸门；已有Watchlist更新/修复，以及用户要求无论结果均完成三报告的任务，直接完整研究。

Terra收决定性事实；同一作者核原件后交 `gate.md`，此时不估分/定价。结果：

- `proceed`：无已核排除条件，继续完整取证；不代表合格。
- `exclude`：已核触发现有一票否决或“不入”任意两条，列规则、原件、适用性和解除条件。交压缩排除报告，标“压缩版，未完成完整三件套；准入排除，未经过完整双复核”，不写入/同步Watchlist。主任务可更新既有公司页的排除说明。
- `needs_evidence`：集中定向补一次决定性缺口；仍缺则具体说明待补证，不因缺证、接口空值或指标不适用判排除。无硬红线但边界不清者进入完整研究。

不另造ROE或主观评分门槛。闸门退出的未派角色记 `not_dispatched_gate_exit`；不适用记 `gate_status=not_applicable`。

### 2. 共享证据与评分底稿

Terra按证据规范先检索本地原件，补决定性缺口后冻结。主任务一次列出影响评分的最小取证范围，交接逐项对照实际内容；补充背景不作评分阻塞条件。补证用 `triplet_evidence_gate.py <coverage.json>` 检查条件ID、引用和版本，再人工核实覆盖；未来计划不能冒充完成年度，存在ID不能冒充内容已齐。未完成的决定性项退回原取证角色局部补齐，不先启动作者改三份正文。

作者先交评分底稿和简明论证：全部分项事实→原规则→得分、总分、关键反证、未知影响及资格门槛。评分是分析判断，执行收尾规范的充分证据原则；不要因定性规则不唯一而自动扩成全域区间。此阶段不先写三份长文，不写同义风险卡或自检长报告。

计划用时：取证约15分钟、评分约10分钟、并行双复核约10分钟、裁决及一次局部修复约15分钟，余量用于验收。主任务在45分钟检查是否尚有决定性缺口，优先完成评分闭环，停止扩展背景和提前润色。时间是调度目标，不允许到时随意扣分、取中点或省略已知重大错误；超过60分钟如实记失败和原因。

### 3. 一次独立双复核与评分批准

两位审核员收到同一冻结评分底稿、论证和中性证据，互不看意见；独立回看决定性原件、重算关键公式，每路至少检查一处索引外遗漏风险，非关键事实按风险抽查。不再单设先盲审风险卡、后阅读全文两段任务。审核先覆盖全部评分与结论，明确已核、错误、合理判断分歧和未知影响；不能以作者脚本替代独立判断。

各交一份审核JSON，保留覆盖、问题和未覆盖项；通过项只记已核。裁决仍匿名处理分歧。全部决定性评分问题闭合后，可单独交付最终得分，记录 `score_state=approved`、准确底稿哈希及两路审核；这不是 `research_state=approved`，不宣称三件套完成，也不触发Watchlist写入。

### 4. 一次裁决，分离研究修复与交付修复

两路意见锁定后，主任务用 `review_trial.py anonymize` 交匿名候选；原件争议由新Astra裁决员核验，唯一台账记录逐候选处置、参数、原验收ID和最小验收条件。不得丢少数意见，不向裁决泄漏审核员身份。

每个问题由裁决明确分流：
- research：事实/口径、来源归属、规则归因、评分、模型、资格或风险判断可能改变。只定向补对应证据和计算；作者先改底稿判断，再改受影响源稿，双路复核受影响结论及联动。
- delivery：判断及真实来源已核，问题仅是确定的引用拼写、状态同步或排版。须裁决写明不影响决策及具体修正对象；程序重新装配或精确补丁，原事实复核员检查改动位置和引用，主任务核版本即可。不能因改叫delivery放行已知错误；来源不确定、语义影响不明自动回research。

主任务按交付规范检查证据ID、共用事实和生成表，再交审核。只修改源，不手改输出；同一事实写在一处，通过标记传播三稿。修复失败先定位输入、引用或判断，不默认再生成全文。

### 5. 有界研究轮次与收尾

研究默认一次合并修复及一次双路定向复查；原重大问题未关、重大新错或决定性新原件可用一次有界例外，由原裁决锁范围，`triplet_repair_writer`接手，使用最后一份内容完整的源稿。记录原因、受影响ID和新证据；换模型不能代替取证。之后不更名绕过上限，按真实边界收尾；新run须补实质证据或用户明确重启。

确定性交付修正不消耗研究重审轮次，也不触发双路全文重读；每批只针对已锁问题局部修正、验证一次。失败必须诊断具体原因，不重复同一操作；若需新的事实或判断，回到尚有额度的研究流程，无额度则明确暂停该缺口。交付未验收仍不发布，但不会撤销已有依据且已批准的资格结论。

每次同时给决策答案、研究状态、交付状态；研究获批不等于报告可发布。保留已核结论与真实未知，不为追求点值填中档或零分。用户暂停任务不自动恢复。

### 6. 完整报告、发布与回写

评分闭合后才展开或修订三份长篇正文。正式定价仍使用两个不同依据的适用主模型、零权重反向验证、三情景、敏感性及机械买入价；模型资料缺口单列为估值暂缓，不推翻已批准评分。长篇报告按交付规范装配；两位原审核员各完整读三份最终报告，但只重新核新估值、改变的判断及正文与已批准底稿的一致性，不重复取证或重做无变化评分。首次完整报告覆盖不可省略，评分阶段不得冒称已完成该覆盖。

主任务核交付清单哈希、已关闭问题及独立验收记录，核三份全文内容及行数150/150/100、市场风险、独立复核、裁决及逐条件验收、唯一参数、链接和版本留存；按公司页规范新建报告版本、更新公司页和索引。只有允许压缩的明确用户范围或准入退出可突破篇幅下限。正式参数发布应用收尾规范的整数总分显示，计算与门槛保留原始分。

公司页/索引及完整研究验收后，按当前Watchlist最高满足档位串行写对应tier，运行 `validate_watchlist.py` 后 `sync_watchlist.ps1`；不合格或未验收不入池，未知不作低分。具体字段及授权沿用项目规则。发现裁决算术错误退回裁决，不自行改判。

## 更新与计量

整套更新先核历史原件版本/重述，再补新财报、从旧截止日连续覆盖的治理事件及共同截止行情。逐维度/假设记录影响或不变依据，不直接继承旧价格；三份完整新版本和双路全文覆盖不减少。最终给“上一版/本版/变化”表：公司分、管理层分、目标价、确定性、机械买入价、档位；首次明确无上一版。

每run维护 `model-routing.json`：`root_thread_id`，各角色 `role/requested_model/requested_effort/agent_id/dispatch_method/actual_model/actual_model_source/status/artifacts`，以及 `gate_status/evidence_version`、冻结稿、`repair_rounds/reopen_reason`、阶段起止和最终状态。实际模型/强度无运行时证据则未知，不取自述作验证。重叠阶段时间不相加当墙钟，排队/等待须标明；无历史计时不回填估算。

用 `triplet_run_audit.py` 在研究结束截止点收集真实计量，只读目标任务树元数据，不导出推理/消息正文。累计末值只计一次，缓存输入及推理输出均是对应总量子集；主任务续跑须按时间窗差分，缺日志/计数回退标未知，不伪造费用。主任务等待完成通知或有界等待，不高频轮询或反复催同义汇报。

优化验收区分首次/更新/修复，比较原件缺陷检出、评分估值差异、回退/返工、未完成率及真实用量；文件字数或缓存命中不等于token/额度节省。规则维护运行入口检查、受影响测试及 `verify-migration`；迁移记录、历史复盘和部署档案不作为每家公司研究必读输入。
