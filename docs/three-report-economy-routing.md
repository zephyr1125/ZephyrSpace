# 三件套经济组合调度

> 明确口令“三件套简化分析XXX”转到[简化模式](three-report-simple-routing.md)，不执行本文件的默认双审调度；普通“三件套分析XXX”仍按下文执行。

完整新建、整套更新及修复的唯一调度真源。用户说“三件套分析XXX”等即使用本组合，不重复询问；用户明确指定的组合优先。局部请求保持原范围。当前采用联合研究过渡版A：评分与估值首次一起送审，研究获批后成文。资料齐备任务以60分钟完整交付为试验目标，质量优先，其次减少token。评分、估值、报告、时间、token分别验收；defer或单元测试通过不等于研究成功。明确局部评分请求仍保持原范围，已有依据可单独批准评分，但完整请求仍须标明未完成。

## 规则归属与读取

同一规则只在所属文件维护；已读且未变内容在同一角色上下文复用。主任务交接给路径、版本、范围和验收条件，不转贴全文。

首次联合底稿阶段只读当前阶段规则、内容模块及适用附件；交付装配、发布、归档和修复命令在对应阶段再读。作者先用底稿规范的init-workpaper生成字段骨架，不靠遍历其他公司样例或读取全部脚本反推格式。工具输出按章节分批，单次汇总须落在返回预算内；发生截断只补缺失范围，已完整读过的规则不再全量重读。PowerShell按行读取用`Get-Content ... | Select-Object -Skip N -First M`；`Get-Content -Raw`返回单个字符串，后接Select-Object不能限制正文行数。财报HTML表格单行过长时提取所需表格及表头、单位、上下文，不用宽泛关键词一次倾倒多份年报。

本地MinerU财报已齐备时，主任务在派发前用`triplet_source_view.py`准备可重建阅读视图并交其路径；作者按证据规范的`--find`命令检索原件，默认每次输出上限12000字符。过宽查询应缩小范围，不抬高工具返回量倾倒整份长表。此步骤只展开原文，不预选评分、不解释会计归属；读取、补充上下文和原件核验仍由作者与独立复核负责。首次交接应直接给现有工具命令，不让各角色重新发现阅读工具。

| 规则 | 唯一位置 | 读取者 |
|---|---|---|
| 模型、阶段、隔离、交付 | 本文件 | 主任务全文；各角色读职责及当前阶段 |
| 原件、期别、数据源、独立核验 | [证据规范](three-report-evidence-contract.md) | 全部角色 |
| 公司/管理层/估值内容 | `deep-prebuy-skill/SKILL.md`、`management-archive/SKILL.md`、`skills/valuation/SKILL.md` | 作者和双复核联合研究时读三者及review-checks；适用附件不省略，裁决按争议定位 |
| 评分/估值计算、审核JSON | [底稿规范](three-report-workpaper.md) | 作者首稿读“作者：先底稿后正文”“模型适配边界”及E4/F1；审核与裁决读其输出格式；主任务读交接命令 |
| 联合接口 | [联合研究接口](three-report-research-contract.md) | 作者首稿读“首次送审”“关键数值”；局部估值审核读输入完整性；修复才读delta/验收依赖；主任务冻结时读版本章节 |
| 交付装配、引用、交付补丁 | [交付规范](three-report-delivery.md) | 研究获批成文时主任务及作者读取；审核/裁决按问题分流读取 |
| 分数展示、决策状态、异常验收 | [收尾规范](three-report-closeout.md) | 作者、复核、裁决、主任务；证据角色不读评价材料 |
| 公司页、市场风险、发布 | [公司页规范](three-report-company-page.md) | 主任务；作者按市场承接内容 |
| 入池、字段、同步 | `data/WATCHLIST_RULES.md`、`data/watchlist_meta.json` | 主任务回写前；作者/审核核资格时读取门槛 |
| 草稿与证据留存 | [Git产物规范](git-artifact-policy.md) | 所有写文件的角色 |

证据角色只按缺口读数据获取附件，不读作者模板。历史案例、接口示例和行业附件按模块的明确触发条件加载；评分细则、适用行业约束、管理层review-checks不能跳过。A/H双重上市额外读 `docs/ah-share-selection.md`，统一选定市场与币种。

## 固定角色与权限

| 角色 | 模型 | 强度 | 职责 |
|---|---|---|---|
| triplet_evidence | gpt-5.6-terra | low | 按明确缺口定向补原件及中性事实；已有可读完整周期资料时不默认单独启动 |
| triplet_writer | gpt-5.6-terra | low | 三份报告、底稿和合并修复 |
| triplet_review_facts | gpt-5.6-terra | low | 独立全文复核，侧重原文与计算 |
| triplet_review_reasoning | gpt-5.6-sol | low | 独立全文复核，侧重模型、归因、反证 |
| triplet_adjudicator | gpt-6-astra | low | 匿名争议裁决、最终参数与验收条件 |

例外接手角色 `triplet_repair_writer` 使用 gpt-5.6-sol / low，仅在下述修复失败触发时启动，替代原作者执行剩余额度内的修复，不增加常驻角色。

角色配置在 `.codex/agents/`，须与上表一致；角色按职责命名，模型仅由配置指定。启动前核对工具加载的角色模型；若仍为旧配置，按下述显式配置方式启动。作者不得兼任审核；裁决不得兼任本轮作者或初审；两路重点不同不减少三份全文覆盖。所有子角色只写分配的产物，不递归启动Agent，不改历史/冻结稿、公司页、索引或Watchlist，不自行提交/推送。主任务仅调度、核交付、串行发布，不重复撰写研究。

优先按自定义角色启动。不可用但工具支持显式配置时，读取对应TOML并传入模型、推理强度和角色指令；`collaboration.spawn_agent` 使用 `reasoning_effort` 与 `fork_turns="none"`，不继承父任务整段历史。两种方式均不可用或运行时明确模型不符，则停止依赖该角色的环节并报告，不静默替换、不无限重试。禁止子Agent的任务不假装完成双复核。主对话模型由用户界面决定，本SOP不修改它。

## 阶段与交接

### 1. 固定范围与准入

主任务固定公司、市场、信息截止日、run目录及历史版本；入口检查命令在 `skills/company-triplet/SKILL.md`。仅新候选适用准入闸门；已有Watchlist更新/修复，以及用户要求无论结果均完成三报告的任务，直接完整研究。

Terra收决定性事实；同一作者核原件后交 `gate.md`，此时不估分/定价。结果：

- `proceed`：无已核排除条件，继续完整取证；不代表合格。
- `exclude`：已核触发现有一票否决或“不入”任意两条，列规则、原件、适用性和解除条件。交压缩排除报告，标“压缩版，未完成完整三件套；准入排除，未经过完整双复核”，不写入/同步Watchlist。主任务可更新既有公司页的排除说明。
- `needs_evidence`：集中定向补一次决定性缺口；仍缺则具体说明待补证，不因缺证、接口空值或指标不适用判排除。无硬红线但边界不清者进入完整研究。

不另造ROE或主观评分门槛。闸门退出的未派角色记 `not_dispatched_gate_exit`；不适用记 `gate_status=not_applicable`。

### 2. 共享证据与评分＋估值联合底稿

先执行[单项低分强制退出](three-report-closeout.md#质量不达标与停止定价)。任一原始评分<70时，后续联合底稿及三报告要求让位于低分退出：仅核验评分依据，确认后登记并停止，不开展估值；已有Watchlist更新/修复亦适用。

作者对全部32分项的事实→规则→判断负责。已有可读完整周期原件时，作者在一次任务内核原件、计算并完成评分底稿；不强制拆成“计划→证据→覆盖表→作者”串行交接。明确缺少原件或需要并行外部补查时，才分派Terra，范围按缺口而非再做整份研究；作者同时完成其余部分。共用事实只收一次，证据角色不评分。

财报齐全不代表历史沿革和外部监管证据齐全。启动时按原规则窗口识别这些非财报缺口：需要补查则立即定向分派证据角色，与作者的财务计算并行；交接实际查询范围、响应及原件定位，不重做全32项覆盖表。作者收到决定性补证后再冻结送审稿，不用“未查到”替代“无异常”，也不把未知映射为较低档位。

评分底稿的32项理由及有效证据引用是统一交接面，未知/缺口只记录差异及其对选档的影响，不再复制一份全32项covered自述表。机械检查见[评分交接](three-report-score-flow.md)，独立双复核仍覆盖全部分项。明确决定性事实未取得时继续补证，不得以未知任意扣分。确需单独委托取证时，可用计划/coverage接口锁范围并阻断公开未查；它不替代作者对充分性的判断。

作者一次交联合底稿：全部32项事实→原规则→得分，以及两个适用主模型、经济依据、三情景、敏感性、现金流/权益/股数桥、零权重反向验证和机械买入价。PE须有同口径历史/可比或经营推导；Ke须有风险构成或有据替代口径；远期现金流及终值须说明增长、利润、再投资、融资的相容关系。运算正确不等于参数合理。未知不得任意扣分；此时不先写三份长文。按[联合研究接口](three-report-research-contract.md)声明joint_research_v1并机械检查，决定性模型缺口不得以deferred占位冒充可审包。已核评分足以停止定价时可交评分＋质量停止依据，须双路核验，缺证不等于质量否决。

主任务送双复核前抽核引用是否覆盖原规则要求的历史窗口，以及“已检索/未见”是否有实际检索记录；仅有当前年事实或公开待查却声称齐备，退回作者完成当前阶段，不把不完整初稿当作可送审稿。该抽核不新增覆盖表、不替代独立审核，耗时照计。

资料齐备任务的计划用时：检查5分钟、联合底稿20分钟、并行审核10分钟、合并修复及裁决15分钟、生成及读稿10分钟。准备、等待、重试全部计入；30分钟无可审包标风险并停止背景扩写，45分钟聚焦决定性问题，55分钟准备恢复点。送审前补稿不是免费循环；超60分钟如实记时间失败，不省略已知错误。并发分派前从同一总预算预留额度，所有角色不得各自重复花剩余额度。

### 3. 一次独立双复核与联合研究批准

两位审核员收到同一冻结评分＋估值底稿、论证和中性证据，互不看意见；独立回看决定性原件、重算关键公式，每路至少检查一处索引外遗漏风险，非关键事实按风险抽查。不再单设先盲审风险卡、后阅读全文两段任务。首次审核同时覆盖全部评分、全部关键估值依据和结论，明确已核、错误、合理判断分歧和未知影响；不能以作者脚本替代独立判断。

各交一份审核JSON，保留覆盖、问题和未覆盖项；通过项只记已核。裁决仍匿名处理分歧。全部决定性评分问题闭合后，可单独交付最终得分，记录 `score_state=approved`、准确底稿哈希及两路审核；这不是 `research_state=approved`，不宣称三件套完成，也不触发Watchlist写入。

### 4. 一次裁决，分离研究修复与交付修复

两路意见锁定后，主任务用 `review_trial.py anonymize` 交匿名候选；原件争议由新Astra裁决员核验，唯一台账记录逐候选处置、参数、原验收ID和最小验收条件。不得丢少数意见，不向裁决泄漏审核员身份。

每个问题由裁决明确分流：
- research：事实/口径、来源归属、规则归因、评分、模型、资格或风险判断可能改变。只定向补对应证据和计算；作者先改底稿判断，再改受影响源稿，双路复核受影响结论及联动。
- delivery：判断及真实来源已核，问题仅是确定的引用拼写、状态同步或排版。须裁决写明不影响决策及具体修正对象；程序重新装配或精确补丁，原事实复核员检查改动位置和引用，主任务核版本即可。不能因改叫delivery放行已知错误；来源不确定、语义影响不明自动回research。

联合研究修复按[接口](three-report-research-contract.md)及[评分交接](three-report-score-flow.md)提交裁决范围delta，评分与估值问题一次合并，由程序生成完整新底稿和差异；双路复查受影响结论及联动，原验收条件不减少。正文按交付规范修复源稿，不手改输出；同一事实写在一处，通过标记传播三稿。主任务先看机械检查异常与差异，必要时定位原文，不反复读取完整JSON。修复失败先定位输入、引用或判断，不默认再生成全文。

裁决涉及可机械验证的经营驱动时，按联合接口在原裁决绑定必需输入；作者送复核前运行check-acceptance，关键派生数字通过number标记生成。遗漏裁决要求或运算不一致先修当前产物，不能把明显未就绪稿送给两位审核者重复找错；准备消耗仍计入原总账，不增加修复轮次。

### 5. 有界研究轮次与收尾

完整请求只有评分与估值都经过首次双路审核后，才开始消耗研究修复额度；两类问题纳入同一清单。两份初审记录绑定同一底稿并声明score/valuation覆盖。研究默认一次合并修复及一次双路定向复查；原重大问题未关、重大新错或决定性新原件可用一次有界例外，由原裁决锁范围，`triplet_repair_writer`接手，使用最后一份内容完整的源稿。记录原因、受影响ID和新证据；换模型不能代替取证。之后不更名绕过上限，按真实边界收尾；新run须补实质证据或用户明确重启。

特殊恢复任务在同一累计预算内明确剩余阶段及额度，不到估值首次审核时自动继承零余额，不另开run清零。

确定性交付修正不消耗研究重审轮次，也不触发双路全文重读；每批只针对已锁问题局部修正、验证一次。失败必须诊断具体原因，不重复同一操作；若需新的事实或判断，回到尚有额度的研究流程，无额度则明确暂停该缺口。交付未验收仍不发布，但不会撤销已有依据且已批准的资格结论。

每次同时给决策答案、研究状态、交付状态；研究获批不等于报告可发布。保留已核结论与真实未知，不为追求点值填中档或零分。用户暂停任务不自动恢复。

### 6. 完整报告、发布与回写

联合研究获批后才展开或修订三份长篇正文，质量停止出口保留适用方法、经营情景与重评条件。未获批可保存局部结论及恢复点，不宣称完整成功。长篇报告按交付规范装配；两位原审核员各完整读三份最终报告，核遗漏、因果、夸大、新判断及与获批底稿的一致性，不重复已核取证。正文新增决定性事实或模型变化须回到底稿，使受影响批准失效；额度耗尽则真实收尾。当前仍是双全审，不启用目标版B或取消行数门槛。

主任务核交付清单哈希、已关闭问题及独立验收记录，核三份全文内容及行数150/150/100、市场风险、独立复核、裁决及逐条件验收、唯一参数、链接和版本留存；按公司页规范新建报告版本、更新公司页和索引。只有允许压缩的明确用户范围或准入退出可突破篇幅下限。正式参数发布应用收尾规范的整数总分显示，计算与门槛保留原始分。

公司页/索引及完整研究验收后，按当前Watchlist最高满足档位串行写对应tier，运行 `validate_watchlist.py` 后 `sync_watchlist.ps1`；不合格或未验收不入池，未知不作低分。具体字段及授权沿用项目规则。发现裁决算术错误退回裁决，不自行改判。

## 更新与计量

有明确token上限的研究或试验先按[预算控制](three-report-budget-control.md)冻结唯一预算配置。每次派发前执行reserve，派发后立即bind并持续watch；非零退出立即由主任务调用interrupt_agent，不先催写总结。未校准时单角色串行，已用量、在途余量、收尾余量及组合上限全部参与准入。不存在平台硬限额保证，不能宣称零超支；到线只停止扩展，不降低研究验收标准。

整套更新先核历史原件版本/重述，再补新财报、从旧截止日连续覆盖的治理事件及共同截止行情。逐维度/假设记录影响或不变依据，不直接继承旧价格；三份完整新版本和双路全文覆盖不减少。最终给“上一版/本版/变化”表：公司分、管理层分、目标价、确定性、机械买入价、档位；首次明确无上一版。

每run维护 `model-routing.json`：`root_thread_id`，各角色 `role/requested_model/requested_effort/agent_id/dispatch_method/actual_model/actual_model_source/status/artifacts`，以及 `gate_status/evidence_version`、冻结稿、`repair_rounds/reopen_reason`、阶段起止和最终状态。实际模型/强度无运行时证据则未知，不取自述作验证。重叠阶段时间不相加当墙钟，排队/等待须标明；无历史计时不回填估算。

用 `triplet_run_audit.py` 在研究结束截止点收集真实计量，只读目标任务树元数据，不导出推理/消息正文。累计末值只计一次，缓存输入及推理输出均是对应总量子集；主任务续跑用`--since`/`--until`作时间窗差分，并逐个`--session <子任务ID>`限定本轮，避免混入历史后代；缺日志/计数回退标未知，不伪造费用。主任务等待完成通知或有界等待，不高频轮询或反复催同义汇报。

优化验收区分首次/更新/修复，比较原件缺陷检出、评分估值差异、回退/返工、未完成率及真实用量；文件字数或缓存命中不等于token/额度节省。规则维护运行入口检查、受影响测试及 `verify-migration`；迁移记录、历史复盘和部署档案不作为每家公司研究必读输入。
