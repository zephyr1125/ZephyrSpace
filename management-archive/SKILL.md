# 管理层档案 · Management Archive

## 定位

弥补普通投资者与专业投资机构之间最大的信息差距——不是"能不能见到老板"，而是**是否有系统框架从公开记录中判断管理层质量**。

核心理念：

> 管理层其实已经在公开材料里暴露了很多东西。核心不是看他说得多好，而是看：**他说过什么，后来做到了没有；他遇到诱惑时有没有克制；遇到困难时有没有诚实。**

本技能输出的档案页面独立于公司 PreBuy 页面，但两者互相引用：
- 公司页 `01-公司/` 引用管理层评分和关键结论
- 深度分析 `深度分析/` 引用管理层档案作为 F 维度（治理结构与管理层）的核心支撑

---

## 与深度分析的关系

| 维度 | 深度分析 (deep-prebuy-skill) | 管理层档案 (本技能) |
|---|---|---|
| 分析对象 | 公司全部 8 个维度 | 仅聚焦管理层这一个维度 |
| 深度 | F 维度占 15/100 分 | 穿透到言行一致性、每笔资本动作、每条公开表述的兑现 |
| 评分 | 管理层是 15 分的子项 | 独立 100 分制管理层评分 |
| 引用关系 | F 维度结论引用本档案 | 为深度分析提供 F 维度完整证据链 |

> **推荐使用顺序**：先建管理层档案 → 再做深度分析 → 深度分析 F 维度直接引用本档案结论。

---

## 核心工作原则

1. **原文优先**：每条关键判断必须有管理层原话/原文支撑，禁止仅凭二手信息下结论。
2. **言行对照**：核心方法不是读他说了什么，而是把他说过的和后来发生的对照。
3. **反证驱动**：不只找支持"好管理层"的证据，必须同步找出反例——他说过但没做到的、前后矛盾的地方。
4. **行动 > 话术**：重点研究资本配置**行为**（分红/回购/定增/并购/股权激励），其次才是**表述**。
5. **年份锚定**：每条说法和每条行为都必须标注年份，建立时间线。
6. **不确定就标注**：无法从公开渠道核实的信息，标注"待核实"而非推测。

## 触发条件

以下任一情况触发本技能：
- 用户明确说"管理层档案 / 老板档案 / 管理层尽调 / 管理层评估" + 公司名或代码
- 用户说"全面分析 XXX"时，管理层档案作为前置步骤（在深度分析之前完成）
- 用户说"看看 XXX 的管理层靠不靠谱"
- 用户想对某公司建立长期跟踪基础

## 数据拉取执行清单

### 第 0 步：基础信息获取

```python
from scripts.cninfo_api import CninfoClient
cninfo = CninfoClient()

# 公司概况（董事长、总经理、法人、董秘、独立董事、成立日期、注册资本、主营业务）
profile = cninfo.company_profile("股票代码")

# 获取 orgId（用于后续公告查询）
```

### 第 1 步：管理层行为数据（并行拉取）

```python
# CNINFO 端
exec_trades = cninfo.executive_trades("股票代码", limit=50)       # 高管持股变动
top10 = cninfo.top10_holders("股票代码")                          # 十大股东（最新）
dividends = cninfo.dividends("股票代码")                          # 分红历史
share_changes = cninfo.share_changes("股票代码")                  # 股本变动（含定增/回购）
penalties = cninfo.company_penalties("股票代码", limit=30)        # 处罚记录
lawsuits = cninfo.company_lawsuits("股票代码", limit=20)          # 诉讼记录
pledge = cninfo.share_pledge("股票代码")                          # 质押状态
freeze = cninfo.share_freeze("股票代码")                          # 冻结状态
irm = cninfo.irm_qa("股票代码", pages=3)                          # 互动易Q&A（最近150条）
ratings = cninfo.investment_ratings("股票代码", limit=30)         # 投资评级历史

# 高管人事变动公告（近5年，关键词过滤）
personnel_anns = cninfo.list_announcements(
    "股票代码", category="", start_date=start_date, end_date=end_date,
    max_pages=3, page_size=30,
)
# 人工/AI 筛选含以下关键词的公告：
# 离任/辞职/聘任/选举/任命/调整/高管/副总裁/总经理/董事长/CTO/CFO/董秘
# 过滤掉：独立董事（非核心管理层）、董事辞职（不兼任高管时影响小）
```

### 第 2 步：理杏仁端交叉验证

调用理杏仁 API Skill，拉取以下端点：
- `cn/company/profile` — 实际控制人、董事长、总经理
- `cn/company/senior-executive-shares-change` — 高管增减持明细
- `cn/company/major-shareholders-shares-change` — 大股东增减持明细
- `cn/company/hot/esc` — 高管增减持汇总（各周期）
- `cn/company/hot/mssc` — 大股东增减持汇总
- `cn/company/hot/df` — 上市以来分红融资统计
- `cn/company/hot/ple` — 质押汇总
- `cn/company/measures` — 证监会监管措施
- `cn/company/inquiry` — 交易所问询函
- `cn/company/dividend` — 分红明细（含派息率）
- `cn/company/announcement` — 近期公告列表

### 第 3 步：智堡端管理层声音

```python
from scripts.wisburg_api import WisburgClient
wisburg = WisburgClient()

# 电话会纪要（管理层原始表述的最重要来源）
calls = wisburg.search_earnings_calls("公司名或代码", first=10)

# 企业研究报告（往往有管理层评价章节）
company_reports = wisburg.search_company_reports("公司名或代码", first=10)

# 资讯流（高管相关快讯）
feed = wisburg.search_feed("公司名 董事长 总经理", first=10)
```

对返回的电话会纪要，**必须获取关键纪要的详情**（`get_earnings_call_detail`），提取管理层对战略/行业/竞争/资本配置的直接表述。

### 第 4 步：年报董事长致辞（如有本地 MD）

检查 `财报/[公司简称]/` 下是否存在 MinerU 转换的年报 Markdown 文件。若存在：
- 定位"董事长致辞"或"董事长报告"章节
- 提取最近 5-7 年的董事长致辞全文或关键段落
- 记录每年的关键表述（战略方向、业绩归因、未来展望、风险提示）

若无本地 MD，通过巨潮资讯在线查看年报 PDF（`list_announcements` 获取链接）。

### 第 5 步：负面事件兜底搜索

```python
from scripts.tavily_search import search_red_flags

# 红旗排查
red_flags = search_red_flags("公司全称", "股票代码")
```

仅用于发现 CNINFO/理杏仁未覆盖的管理层负面事件（如媒体调查报道、行业口碑等）。

## 档案页面模板

> 📄 **独立模板文件**：`管理层档案/管理层档案模板.md`（可直接复制使用）
>
> 🔑 **核心要求**：档案开头必须是「📊 快速参考」卡片（总分、评级、类型、一句话评价、7维度速览、优缺点、跟踪指标），让读者无需翻阅全文就能获取核心结论。卡片之后才是11章节详细分析。
>
> ⚠️ 卡片中的每一项都必须与正文严格一致（评分联动原则）。

输出到 `管理层档案/[公司简称] 管理层档案 [评分] YYYY-MM-DD.md`，格式如下：

> 命名示例：`管理层档案/长江电力 管理层档案 96 2026-05-31.md`
>
> 评分取综合评分（100分制整数），日期取分析日期，标在文件名中方便按质量快速筛选。

> ⚠️ **强制规范，禁止省略评分**
> - ✅ 正确：`澜起科技 管理层档案 73 2026-06-15.md`
> - ❌ 错误：`澜起科技 管理层档案 2026-06-15.md`（漏评分）
> - ❌ 错误：`澜起科技 管理层档案.md`（漏日期+评分）
>
> 评分是文件名第三个字段，必须存在。下游脚本（如 To Do loop 的缓存命中检查 `scripts/todo_check_cache.py`）会从文件名提取评分，缺失会触发重跑或回写失败。
> 写完文件后立刻 `ls 管理层档案/[公司简称]*` 自检命名格式。

## 六、组织与人才

### 6.1 高管变动历史 ⭐

> 核心问题：**谁走了、为什么走、谁接任、从哪来。** 这是判断管理层稳定性和继任体系质量的关键维度。
> 单次高管离任在大型企业是正常现象；但短期密集离任、核心技术/业务负责人空缺、或全数依赖外部空降接任，则是治理红旗。

**高管变动时间线**（近 5 年，非独立董事/高管层及以上）：

| 年份 | 姓名 | 原职务 | 变动类型 | 原因（公告原文） | 接任者 | 接任者来源 | 影响评估 |
|------|------|--------|---------|-----------------|--------|-----------|---------|
| YYYY | | | 离任/上任 | | | 内部晋升/外部空降 | |

**变动模式分析**：

| 维度 | 数据 | 评估 |
|------|------|------|
| 近 5 年 C-suite 离任人数 | xx 人 | |
| 近 3 年 C-suite 离任人数 | xx 人 | |
| 是否存在短期集中离任（12 个月内 ≥3 人） | 是/否 | |
| 离任原因分布 | 个人原因 x 人 / 任期届满 x 人 / 工作调整 x 人 | |
| 接任者内部晋升比例 | xx%（内部晋升 / 总接任） | |
| 关键岗位（CEO/CTO/CFO）是否有长期空缺 | 是/否 | |
| 离任者是否持有公司股份（利益绑定程度） | 持有 / 少量 / 零持股 | |

**评估标准**：
- **正常**：个别离任 + 内部晋升接任 + 无缝过渡 + 原因清晰
- **需关注**：12 个月内 ≥2 人离任、或关键岗位空缺 > 6 个月、或连续依赖外部空降
- **红旗**：12 个月内 ≥3 人密集离任、或 CEO/CTO/CFO 同时空缺、或离任者均为核心业务负责人且无股份绑定

### 6.2 核心技术人员与组织

- 核心技术人员保留情况（研发离职率、股权激励覆盖）

- 激励机制的合理性与约束力（股权激励解锁条件是否严格）

### 第 2 步：双 Agent 并行审核（强制步骤）

初稿写完后，**并行启动两个子 Agent**，分别执行以下审核任务：

#### Agent A：逻辑一致性审核

**提示词模板**：

```
你是管理层尽调审核专家。请审核以下管理层档案的逻辑一致性：

[粘贴完整档案 Markdown]

审核要点（逐项检查）：

1. **言行一致性追踪的自洽性**：
   - 每条"关键表述"是否都能找到对应的"兑现/未兑现"证据？
   - 正面案例和失信案例的权重是否平衡？（如果只有正面没有负面，是否遗漏了反证？）
   - 一致性评估的结论是否与表格中的兑现率一致？

2. **评分内在一致性**：
   - 各维度得分是否与正文中的证据匹配？
   - 如果正文大量笔墨描述"资本配置纪律优秀"但资本配置仅得 15/25，是否存在自相矛盾？
   - 如果正面信号远多于负面信号，总分却偏低，是否合理？
   - Σ(各维度得分) == 汇总表总分？逐项加总校验。

3. **结论与证据的匹配度**：
   - "一句话评价"是否与评分和正文一致？
   - "最突出的优点"和"最需要警惕的问题"是否在正文中有充分展开？
   - 管理层类型定位（托付重仓/中性/跟踪/减分项）是否与实际评分匹配？

4. **时间线自洽性**：
   - 言行一致性追踪表中的年份顺序是否准确？
   - 资本配置时间线是否与言行时间线前后一致？
   - 危机处理时间线是否与其他表中的事件年份一致？

5. **过渡词与模糊表述检测**：
   - 是否存在"近年来""长期""持续""一贯"等无锚定年份的模糊表述？
   - 是否存在"极好""极强""卓越"等形容词但缺乏对应的具体证据支撑？
   - 是否存在"似乎""可能""应该"等推测性表述替代确定性判断？

请给出：
- 每条审核要点的通过/不通过状态
- 不通过项的具体位置（引用原文）+ 问题描述
- 综合判断：是否需要进入 P1 修复
```

[粘贴完整档案 Markdown]

审核要点（逐项检查）：

1. **人物信息准确性**：

### 第 3 步：P1 修复（含评分联动检查，强制步骤）

P1 修复不只是"把错误的文字改对"——**每次 P1 修复后必须显式检查评分是否需要联动调整。**

#### P1 修复标准流程

1. **逐条修复**审核 Agent 标记的 P0/P1 问题
2. **每个修复完成后，执行评分联动检查**：

```
P1修复「[问题描述]」后，评分联动检查：
- 影响维度：[具体维度名称] → [子项名称]
- 修正前叙述：[原始错误描述] → 扣分逻辑
- 修正后事实：[修正后的正确描述]
- 重审判断：[分数是否调整？调多少？为什么？]
- 决定：[维度分数从 X→Y / 维持 X 分不变]
```

3. **分数不变时也要记录**（留下审阅轨迹）：
   > P1修复「XXX」后评分联动检查：影响维度 → 综合判断后分数维持 X 分不变，原因：[原因]。

4. **同步更新所有引用评分的位置**（缺一不可）：
   - 评分汇总表（维度行 + 总分行）
   - 综合结论中的评级段
   - 公司页深度分析引用区块中的管理层评分（如公司页引用了本档案评分）
   - 总分算术自校验：`Σ(各维度得分) == 汇总表总分`

#### 管理层档案高频 P1 修复 → 评分联动速查表

| P1 修复类型 | 最可能影响的维度 | 分数变化方向 |
|---|---|---|
| 减持/增持方向写反 | 对股东友好度 | 可能上调（原夸大减持负面影响） |
| 处罚金额低估/高估 | 监管与合规 → 诚信与透明度 | 低估→下调；高估→上调 |
| 董事长/总经理姓名错误 | （不直接影响评分，但严重损害可信度） | P0 强制修复 |
| 言行兑现判断反转（原判"已兑现"→实为"未兑现"） | 诚信与透明度 | 下调 |
| 回购/分红金额偏差 > 20% | 资本配置能力 + 对股东友好度 | 按比例调整 |
| 管理层表述断章取义（原文摘录缺失关键限定词） | 诚信与透明度 / 表达清晰度 | 可能下调 |
| 高管变动时间线遗漏（未发现多人短期集中离任模式） | 组织与人才能力 → 高管稳定性 | 可能下调（发现新模式后重新评估） |
| 评分算术不闭合 | 全表 | 必须修正至闭合 |

#### 底线原则

> **任何 P1 修复，都必须走完"修复事实 → 评价分数影响 → 决定是否调分 → 更新所有引用"完整闭环，不允许只修复文字不检查分数。**

### 管理层档案特有常见坑（附历史实例参考）

以下坑来源于深度分析双 Agent 审核中与治理/管理层相关的历史发现，管理层档案场景下同样高发：

#### 坑 M1：管理层信息依赖陈旧记忆——姓名/职位写错

**根因**：依赖"这家公司一直是XX领导"的历史记忆，未核查最新年报。董事长/总经理的变动可能发生在任意年份。

**正确做法**：
- 管理层姓名和职位必须从**当年年报**直接提取（巨潮资讯/港交所披露易）
- CNINFO `company_profile` 和理杏仁 `cn/company/profile` 均返回最新数据，优先使用
- 若年报 MD 文件存在，核对 MD 中管理层名单与 API 返回是否一致
- **任何情况下禁止依赖记忆或历史惯例**

**检查要点**：档案起草前，先问自己——"我用的管理层名字，是公司的**现任**管理层吗？"

#### 坑 M2：监管处罚描述——多次独立事件混淆为一条

**根因**：记忆中"这家公司被罚过XX"→合并写为一条笼统描述，丢失细节和量级。

**管理层档案的正确格式**（与深度分析坑9对应）：

| 年份 | 类型 | 机构 | 事项 | 金额（精确到单位） | 状态 |
|------|------|------|------|-------------------|------|
| YYYY | 处罚 | XX | XX | XX元（非万元/亿元） | |

> ⚠️ 每次独立事件必须单独一行，绝不合并。事后回顾时，记忆中的"50亿"与档案中的"50万元"差距4个数量级。

#### 坑 M3：言行兑现判断过于宽松——把"正在进行"当"已兑现"

**根因**：管理层说"将加大研发投入"→第二年研发费用确实增加→标记"✅ 已兑现"。但这只是执行了预算，不代表创造了价值。

**正确做法**：言行兑现判断必须区分三个层次：
- ⏳ **执行中**：钱花出去了，但效果未知（如"AI Capex 翻倍"）
- ✅ **已兑现**：有明确的成果指标（如"云业务2025年实现50亿经营利润"）
- ❌ **未兑现**：明确的结果与承诺不符

**禁止**：把 "执行了承诺的动作"自动等同于 "兑现了承诺的结果"。

#### 坑 M4：资本配置动作遗漏——仅看A股增发/配股，遗漏港股/可转债等工具

**根因**：与深度分析坑14同类。管理层档案的"资本配置记录"必须覆盖所有融资工具。

**融资工具核查清单**：

| 工具类型 | 是否构成潜在摊薄 | 查询来源 |
|---|---|---|
| A股增发（含定增/公开增发） | ✅ 直接摊薄 | 巨潮资讯 / 理杏仁 |
| A股配股 | ✅ 直接摊薄 | 巨潮资讯 |
| 可转债（A股/H股） | ✅ 转股后摊薄 | 巨潮资讯 / 港交所披露 |
| H股增发 | ✅ 直接摊薄 | 港交所披露易 |
| 优先股 | ✅ 转换后摊薄 | 巨潮资讯 |
| 股票期权/限制性股票激励 | ⚠️ 有限摊薄 | 股权激励方案公告 |

#### 坑 M5：对大股东减持的判断忽略增持记录

**根因**：注意到减持就写"持续减持"，忽略了期间也有增持行为。与深度分析坑15同类。

**正确做法**（以绿的谐波实例为鉴）：
- 减持不能只看方向，必须看**时间分布**和**买卖双向**
- 如果大股东在底部增持过（哪怕规模小于减持），必须在言行一致性追踪中记录
- "2023-2025年持续减持"→ ❌ 错误（忽略中间增持）
- "2024年9月底部增持 + 2025年6-9月集中套现"→ ✅ 正确（保留完整叙事）

#### 坑 M6：分红/回购金额口径混淆——公告金额 vs 实际执行金额

**根因**：管理层档案中引用的回购金额可能来自不同来源（年报、电话会、公告），口径不同导致数字不一致。

**正确做法**：
- 回购金额统一使用**年报实际执行口径**（非计划/公告上限）
- 分红金额区分"每股DPS"和"总分红金额"，注明币种（HKD/CNY）
- 如果电话会指引和实际执行有差异，在资本配置记录中单独标记

#### 坑 M7：管理层原文摘录断章取义——缺失关键限定词

**根因**：为了支持某个判断，只摘录管理层表述中有利/不利的部分，忽略上下文中的限定条件。

**正确做法**：
- 每条原文摘录必须保留完整语境（至少前后各1-2句）
- 如果管理层说了"在XX条件下，我们预计YY"，不能只摘"我们预计YY"
- 标注"（摘要）"的条目，必须在脚注或附录中提供完整上下文链接

#### 坑 M8：高管变动仅凭记忆判断——未建立系统时间线

**根因**：注意到个别高管离任就写"管理层动荡"，或反之只凭印象写"团队稳定"，均未拉取公告建立时间线。美的 CTO 卫昶离职（2026-05）+ 伏拥军、柏林等多人先后离任——如果只看到卫昶一条公告而忽略整体模式，就会低估问题的严重性。

**正确做法**：
- 高管变动不能凭记忆。必须拉取近 5 年人事变动公告，逐条记录建立时间线（见六、组织与人才 > 6.1 高管变动历史模板）
- 区分：正常退休/任期届满 vs 个人原因中途辞职 vs 工作调整（调岗）——三者含义完全不同
- 关注离任者是否持股：**零持股的高管离任"个人原因"时，利益绑定弱的可能性更大**
- 接任者来源是核心信号：内部晋升→治理体系成熟；外部空降集中出现→内部人才梯队可能薄弱
- 短期密集离任（12 个月内 ≥3 人）自动触发红旗——不论单次公告措辞多温和

**检查要点**：在写"管理层团队稳定"之前，先看看近 3 年有多少高管走了、接任者从哪来。

## 注意事项

1. **港股公司**：CNINFO 不覆盖港股，管理层数据以理杏仁 `hk/company` 端点为主，智堡电话会纪要补充。
2. **央企/国企**：管理层评分标准需调整——资本配置自主权有限，重点是看代理问题（有无利益输送、过度扩张、不作为）。
3. **创始人公司 vs 职业经理人公司**：创始人公司的管理层分析重心在创始人本人；职业经理人公司重心在激励制度、内部控制、董事会制衡。
4. **年报 MD 文件是金矿**：如果 `财报/[公司名]/` 下有 MinerU 转换的年报，务必优先读取董事长致辞章节——这是最接近"和管理层聊天"的公开材料。
5. **电话会纪要的原始价值**：智堡电话会纪要保留了 Q&A 环节管理层对尖锐问题的即时反应——这比年报致辞更有判断价值。
6. **双 Agent 审核不可跳过**：第 2-3 步（双 Agent 审核 + P1 修复）是强制步骤——与深度分析 SOP 第 2-3 步对齐。子 Agent 审核提示词已在上方模板中提供，可直接复制使用。
7. **🔴 档案长度硬性要求（严禁偷懒）**：管理层档案**不得少于 150 行**（Markdown 行数），正常应达到 200-350 行。11 个章节缺一不可——小市值/新上市公司"公开资料少"不能成为跳章的借口：资料少的部分就诚实标注"信息不足"而非跳过整个章节。速览卡(📊 快速参考)不能替代正文分析——速览卡是摘要，正文是依据。此条已纳入格式规则，**初稿行数 < 150 行视为不合格，不得进入双 Agent 审核**。
