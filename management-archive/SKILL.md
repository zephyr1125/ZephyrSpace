# 管理层：研究与评分核心规则

仅作为 `skills/company-triplet/SKILL.md` 的仓库内部模块，不单独安装或启动。完整流程以 `docs/three-report-economy-routing.md` 为唯一调度真源，数据源以 `docs/three-report-evidence-contract.md` 为准；旧段落中的独立审核、全源拉取、提交及回写指令不执行。评分标准、研究内容、行业约束及原件核验要求不变。

总分展示遵守 `docs/three-report-closeout.md` 的整数规则；分项、原始总分与门槛不变。

## 按需读取

- 作者和两位审核员必读本文件的研究模板、七维评分及评分联动规则。模板含检查要求，不是可整体跳读的空白格式。
- 两位审核员首次全文审核必读 [管理层审核检查项](references/review-checks.md)；只执行其中内容检查，不另开 Agent、不复制长提示词。作者有具体缺口时按需查阅。
- Terra 或补证角色按缺口读 [数据获取](references/data-access.md)；作者收尾读 [速览卡与关联格式](references/report-closeout.md)，公司页仍仅由主 Agent 回写。
- [历史坑例](references/pitfalls.md)触发索引：当前人物M1；处罚M2；兑现M3；融资M4；增减持M5；回报执行M6；原话限定词M7；人事时间线M8。相关事项出现时读取对应章节，不全量重读案例。
- [历史上下文](references/legacy-context.md)不参与执行。下文“第2–3步”指统一三件套双复核及有界修复，不构成第二套流程。

## 核心工作原则

1. **原文优先**：每条关键判断必须有管理层原话/原文支撑，禁止仅凭二手信息下结论。
2. **言行对照**：核心方法不是读他说了什么，而是把他说过的和后来发生的对照。
3. **反证驱动**：不只找支持"好管理层"的证据，必须同步找出反例——他说过但没做到的、前后矛盾的地方。
4. **行动 > 话术**：重点研究资本配置**行为**（分红/回购/定增/并购/股权激励），其次才是**表述**。
5. **年份锚定**：每条说法和每条行为都必须标注年份，建立时间线。
6. **不确定就标注**：无法从公开渠道核实的信息，标注"待核实"而非推测。

## 档案页面模板

> 📄 **独立模板文件**：`管理层档案/管理层档案模板.md`（可直接复制使用）
>
> 🔑 **核心要求**：档案开头必须是「📊 快速参考」卡片（总分、评级、类型、一句话评价、7维度速览、优缺点、跟踪指标），让读者无需翻阅全文就能获取核心结论。卡片之后才是11章节详细分析。
>
> ⚠️ 卡片中的每一项都必须与正文严格一致（评分联动原则）。

输出到 `管理层档案/[公司简称] 管理层档案 [评分] YYYY-MM-DD.md`，格式如下：

> 命名示例：`管理层档案/长江电力 管理层档案 96 2026-05-31.md`
>
> 评分取综合评分（100分制整数），日期取分析日期，标在文件名中方便按质量快速筛选。

> ⚠️ **强制规范，禁止省略评分**
> - ✅ 正确：`澜起科技 管理层档案 73 2026-06-15.md`
> - ❌ 错误：`澜起科技 管理层档案 2026-06-15.md`（漏评分）
> - ❌ 错误：`澜起科技 管理层档案.md`（漏日期+评分）

> 评分是文件名第三个字段，必须存在。下游脚本（如 To Do loop 的缓存命中检查 `scripts/todo_check_cache.py`）会从文件名提取评分，缺失会触发重跑或回写失败。

## 六、组织与人才

### 6.1 高管变动历史 ⭐

> 核心问题：**谁走了、为什么走、谁接任、从哪来。** 这是判断管理层稳定性和继任体系质量的关键维度。
> 单次高管离任在大型企业是正常现象；但短期密集离任、核心技术/业务负责人空缺、或全数依赖外部空降接任，则是治理红旗。

**高管变动时间线**（近 5 年，非独立董事/高管层及以上）：

| 年份 | 姓名 | 原职务 | 变动类型 | 原因（公告原文） | 接任者 | 接任者来源 | 影响评估 |
|------|------|--------|---------|-----------------|--------|-----------|---------|
| YYYY | | | 离任/上任 | | | 内部晋升/外部空降 | |

**变动模式分析**：

| 维度 | 数据 | 评估 |
|------|------|------|
| 近 5 年 C-suite 离任人数 | xx 人 | |
| 近 3 年 C-suite 离任人数 | xx 人 | |
| 是否存在短期集中离任（12 个月内 ≥3 人） | 是/否 | |
| 离任原因分布 | 个人原因 x 人 / 任期届满 x 人 / 工作调整 x 人 | |
| 接任者内部晋升比例 | xx%（内部晋升 / 总接任） | |
| 关键岗位（CEO/CTO/CFO）是否有长期空缺 | 是/否 | |
| 离任者是否持有公司股份（利益绑定程度） | 持有 / 少量 / 零持股 | |

**评估标准**：
- **正常**：个别离任 + 内部晋升接任 + 无缝过渡 + 原因清晰
- **需关注**：12 个月内 ≥2 人离任、或关键岗位空缺 > 6 个月、或连续依赖外部空降
- **红旗**：12 个月内 ≥3 人密集离任、或 CEO/CTO/CFO 同时空缺、或离任者均为核心业务负责人且无股份绑定

### 8.1 处罚检索必须同时覆盖「证券监管」与「行业监管」（强制）

> ⚠️ **单一依赖证监会/交易所处罚会遗漏行业主管部门的处罚，导致治理评分虚高。** 管理层廉洁与合规记录检索必须同时拉取两个维度：

| 监管维度 | 适用机构（检索源） | 典型处罚类型 |
|---|---|---|
| **证券监管** | 证监会（measures）、交易所（上交所/深交所问询函）、央行（反洗钱/支付结算） | 信息披露违规、内幕交易、操纵市场、财务造假、问询函 |
| **行业监管** | 国家金融监督管理总局（原银保监会，银行/保险）、证监会（券商）、行业主管部门（如国资委、工信部、生态环境部、药监局、应急管理部等，依公司行业而定） | 业务违规罚单、审慎监管措施、责令整改、行业准入处罚、环保/安全/质量处罚 |

**执行规则**：
- **银行/保险/券商**：行业监管以**国家金融监督管理总局（金监总局）/原银保监会**为主检索源（如银保监罚决字、金监罚决字），与证监会/交易所处罚并列记录。招行、工行等银行的 "监管罚单"（如信贷管理违规、理财业务违规、外汇业务违规）多来自金监总局，**不检索即遗漏**。
- **制造业/资源/消费等**：行业监管以**生态环境部（环保罚单）、应急管理部（安全生产）、药监局（GMP/质量）、市场监管总局（反垄断/质量）** 等为准，依公司行业选择。
- **检索方式**：优先用理杏仁 `cn/company/measures`（含多监管源）+ `cn/company/inquiry`；行业监管罚单若 API 未覆盖，Tavily 兜底搜索 `{公司名} {行业监管关键词} 处罚 罚单`（如银行用"银保监 罚决 信贷"，制造用"环保处罚 生态环境"），且 Tier ≥ T2 才触发。
- **记录要求**：证券监管与行业监管罚单**分列**，不得互相替代；每条仍须独立成行、金额精确、注明处罚机构层级（会/局/分局）。

| **P0** | 致命错误：管理层姓名写错、处罚金额差一个数量级、评分算术不闭合 | **必须修复**；完整三件套按SOP定向复查与有界例外，单独任务复查错误范围及联动 |
| **P1** | 重要错误：事实描述不准确、时间线错位、评分与证据不匹配、来源缺失 | **必须修复**，进入第3步（含评分联动检查） |
| **P2** | 轻微瑕疵：模糊表述（"近年来"→建议改为具体年份）、形容词过度使用 | 选择性修复，不阻塞交付 |

> ⚠️ **P0/P1 问题未修复前，档案不得视为完成。**

---

### 第 3 步：P1 修复（含评分联动检查，强制步骤）

P1 修复不只是"把错误的文字改对"——**每次 P1 修复后必须显式检查评分是否需要联动调整。**

#### P1 修复标准流程

1. **逐条修复**审核 Agent 标记的 P0/P1 问题
2. **每个修复完成后，执行评分联动检查**：

```
P1修复「[问题描述]」后，评分联动检查：
- 影响维度：[具体维度名称] → [子项名称]
- 修正前叙述：[原始错误描述] → 扣分逻辑
- 修正后事实：[修正后的正确描述]
- 重审判断：[分数是否调整？调多少？为什么？]
- 决定：[维度分数从 X→Y / 维持 X 分不变]
```

3. **分数不变时也要记录**（留下审阅轨迹）：
   > P1修复「XXX」后评分联动检查：影响维度 → 综合判断后分数维持 X 分不变，原因：[原因]。

4. **同步更新所有引用评分的位置**（缺一不可）：
   - 评分汇总表（维度行 + 总分行）
   - 综合结论中的评级段
   - 公司页深度分析引用区块中的管理层评分（如公司页引用了本档案评分）
   - 总分算术自校验：`Σ(各维度得分) == 汇总表总分`

#### 管理层档案高频 P1 修复 → 评分联动速查表

| P1 修复类型 | 最可能影响的维度 | 分数变化方向 |
|---|---|---|
| 减持/增持方向写反 | 对股东友好度 | 可能上调（原夸大减持负面影响） |
| 处罚金额低估/高估 | 监管与合规 → 诚信与透明度 | 低估→下调；高估→上调 |
| 董事长/总经理姓名错误 | （不直接影响评分，但严重损害可信度） | P0 强制修复 |
| 言行兑现判断反转（原判"已兑现"→实为"未兑现"） | 诚信与透明度 | 下调 |
| 回购/分红金额偏差 > 20% | 资本配置能力 + 对股东友好度 | 按比例调整 |
| 管理层表述断章取义（原文摘录缺失关键限定词） | 诚信与透明度 / 表达清晰度 | 可能下调 |
| 高管变动时间线遗漏（未发现多人短期集中离任模式） | 组织与人才能力 → 高管稳定性 | 可能下调（发现新模式后重新评估） |
| 评分算术不闭合 | 全表 | 必须修正至闭合 |

#### 底线原则

> **任何 P1 修复，都必须走完"修复事实 → 评价分数影响 → 决定是否调分 → 更新所有引用"完整闭环，不允许只修复文字不检查分数。**

## 注意事项

1. **港股公司**：CNINFO 不覆盖港股，管理层数据以理杏仁 `hk/company` 端点为主，智堡电话会纪要补充。

4. **年报 MD 文件是金矿**：如果 `财报/[公司名]/` 下有 MinerU 转换的年报，务必优先读取董事长致辞章节——这是最接近"和管理层聊天"的公开材料。

7. **🔴 档案长度硬性要求（严禁偷懒）**：管理层档案**不得少于 150 行**（Markdown 行数），正常应达到 200-350 行。11 个章节缺一不可——小市值/新上市公司"公开资料少"不能成为跳章的借口：资料少的部分就诚实标注"信息不足"而非跳过整个章节。速览卡(📊 快速参考)不能替代正文分析——速览卡是摘要，正文是依据。此条已纳入格式规则，**初稿行数 < 150 行视为不合格，不得进入双 Agent 审核**。
