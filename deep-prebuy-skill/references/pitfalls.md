## 数据采坑手册（执行经验汇总）

> 以下为实际执行中踩过的坑，每次执行前必读。

### 坑 1：理杏仁 gzip 解码偶发失败

**现象**：`json.loads(gzip.decompress(resp.content))` 抛 `OSError: Not a gzip file`。
**原因**：API 有时即使请求了 `Accept-Encoding: gzip`，仍直接返回明文 JSON。
**修复**：`lx_post` 函数必须用 try/except 双路解码（见上方代码模板）。

---

### 坑 2：fs/non_financial 响应字段不是扁平 key

**现象**：`d.get("y.ps.toi.t")` 返回 `None`。
**原因**：`metricsList` 的点号路径是**请求语法**，响应体是嵌套 dict，不是扁平 key。
**修复**：必须按嵌套层级访问：

```python
y = d.get("y", {})
toi = y.get("ps", {}).get("toi", {}).get("t", "N/A")
```

---

### 坑 3：fs/non_financial 无效字段静默返回 None

**现象**：`metricsList` 中写了 `y.ps.ocf.t`（经营现金流）或 `y.bs.se.t`（净资产），API 不报错，但数据返回 None。
**有效字段**（已实测）：`y.ps.toi.t` / `y.ps.np.t` / `y.bs.ta.t` / `y.bs.tl.t`
**OCF 获取**：改用东方财富 `MGJYXJJE`（每股经营现金流）字段计算。
**净资产**：必须手算 = `ta - tl`。

---

### 坑 4：fundamental/non_financial 用年末日期历史 ROE 全为 None

**现象**：传入 `date: "2020-12-31"` 等年末日，所有 ROE/PE/PB 字段返回 None。
**原因**：`fundamental/*` 必须传**最近交易日**（非周末/节假日/年末）才能返回数据。
**修复**：
- 当前估值 → 用 `last_trading_day()` 计算最近交易日
- 历史年度 ROE → 改用东方财富 API 的 `WEIGHTAVG_ROE` 字段

---

### 坑 5：Python 脚本必须写成 .py 文件

**现象**：将多行 Python 代码嵌入 PowerShell `-c "..."` 或 heredoc，语法报错（f-string内引号转义、缩进等问题）。
**原因**：PowerShell 不支持 Unix-style `<< 'EOF'`；多行 `-c` 字符串中的内嵌引号极易冲突。
**修复**：用 `Set-Content` 将 Python 代码写入 `_tmp_xxx.py`，再用 `python _tmp_xxx.py` 执行，分析结束后 `Remove-Item` 清理。

---

### 坑 6：新股IPO专项分析陷阱汇总

> 以下5个坑均在嘉德利（603435）2026-05-13 深度分析中实际踩过，来源：用户核验反馈（全部质疑均有数据支撑）。

---

#### 坑 6.1：发行PE口径年份错误

**现象**：将发行PE（如29.72x）的计算基准年份写成"上一自然年"（如2024年）。

**正确做法**：发行PE以**最近完整披露财务年度**为基准，取自**招股意向书（发行版）**。若发行意向书已含2025年全年数据，则PE基准就是2025年。
- 嘉德利实例：2026年5月发行，发行意向书含2025全年净利2.435亿，PE 29.72x = 基于2025年（而非2024年）。
- 验证方法：以发行公告中"按照发行价格计算，发行人2025年摊薄后市盈率为29.72倍"等原文表述为准。

---

#### 坑 6.2：必须使用发行版招股书，受理版已过时

**现象**：用11月受理版招股书做分析，而实际发行可能已更新到次年5月的发行版，数据相差整4-6个月的完整年度财报。

**表现（嘉德利实例）**：
- 受理版（2025年11月）：含2025H1数据，只能年化推算全年
- 发行版（2026年5月）：含2025全年实际数据（营收7.571亿、净利2.435亿）
- 两者差距：受理版推算NP~2.5亿，发行版实际2.435亿；受理版推算OCF/净利35.8%，发行版披露97%

**正确做法**：对申购日临近的新股，**必须优先获取发行意向书（最终发行版）**，来源：上交所/深交所 e-Registration 系统、发行人官网、证监会 e-Disclosure。不可仅依赖初次受理版。

---

#### 坑 6.3：OCF质量不能用"每百元营业收入现金留存"间接推算

**现象**：用媒体报道或招股书"每百元营业收入现金留存"（= 经营活动净现金流/营收×100）推算OCF/净利比值。

**问题**：
- "每百元营业收入现金留存"分子是**经营活动净现金流**，分母是**营收**，不是净利润，两者口径不同
- 在扩产期，资本性支出大量增加会压低该指标，但这是**投资现金流出**，不影响经营现金流质量
- 嘉德利实例："每百元营业收入现金留存"为-42.83元，表面看起来很差；而实际OCF/净利2024年93%

**正确做法**：
1. **优先**：直接查招股书披露的"现金收入比"（当期营收中收到现金的比例），这才是收入质量指标
2. **次选**：用东方财富 `MGJYXJJE`（每股经营活动现金流）× 股本 = OCF总额，再除以净利润
3. **永远区分**：OCF（经营现金流）vs FCF（自由现金流=OCF-资本支出），两者用途不同

---

#### 坑 6.4：招股书直接披露"现金收入比"，应优先使用

**现象**：忽视招股书中直接披露的"现金收入比"指标，转而自行估算。

**说明**：
- 招股书中的"现金收入比" = 当期营收中实际收到现金/营收，反映应收账款质量和收入真实性
- 这是比OCF/净利更直接的**收入质量**衡量指标，不受资本支出影响
- 嘉德利实例：2023年91.70%→2024年96.07%→2025年99.17%，三年持续显著改善，是极高质量信号
- 若现金收入比持续>95%且提升，基本可排除收入虚增风险

**正确做法**：查看招股书财务分析章节中的"现金收入比"或"收现比"。若该指标>90%且稳定/上升，E2评分可给4-5分（健康）。

---

#### 坑 6.5：生产线/产能数据在建设期持续更新，受理版可能落后数条

**现象**：引用受理版披露的"7条生产线"，而实际已投产8条（在建3条）。

**规律**：
- 申请IPO的制造业公司通常处于主动扩产期，受理版（递交材料时）与发行版（正式发行时）之间往往隔6-18个月，新线可能已陆续投产
- 嘉德利实例：受理版披露7条→发行版已投产8条（含4条同步双向拉伸线），另在建3条

**正确做法**：发行版招股书的"产能与产量"章节必须重新核查，不能沿用受理版数据。重点关注：投产线数量、在建线数量、产能利用率口径（是否有"标准化"和"实际"两套数字）。

---

### 坑 7：业务分部数字—父分部合计值误作子分部收入（腾讯2026-05实例）

> 来源：腾讯2026-05-13深度分析，用户事后核验发现。

**现象**：将"VAS（增值服务）合计 3,692.81亿"写成"游戏约3,500亿"，误把父分部合计值等同于最大子分部的收入。

**实际情况**：
- VAS 合计 3,692.81亿 = 国内游戏1,642亿 + 国际游戏774亿 + 社交网络增值1,277亿
- 纯游戏收入 = 1,642 + 774 = **2,416亿**（非3,500亿）
- 3,500亿 ≈ 整个VAS板块，不是游戏板块

**根因**：没有从年报分部收入表直接提取数字，而是依赖记忆/推算。

**修复规则**：
1. B1业务板块的每一个金额，必须能在年报"Revenues by Segment"或"分部信息"章节中找到对应行
2. 提取时先写父分部合计，再逐项列子分部，并验证：子分部之和 = 父分部合计（浮动 ≤ 1% 可接受舍入误差）
3. 若子分部拆分无官方披露，明确注明"官方未单独披露，以下为估算"

### 坑 8：FCF口径—简化计算值vs公司官方定义值（腾讯2026-05实例）

> 来源：腾讯2026-05-13深度分析，用户事后核验发现。

**现象**：FCF写成2,156亿，实为"OCF - Capex paid"的简化计算；腾讯官方披露FCF为**1,826亿**，差额约330亿。

**腾讯官方FCF定义**（FY2025 Earnings Presentation）：
> FCF = OCF - Capex paid - media content payments - lease liabilities payments
> = 3,031亿 - 883亿 - 约200亿 - 约120亿 = **1,826亿**

**通用修复规则**：
1. **优先查找公司自定义FCF**：年报业绩演示文稿（Earnings Presentation/Results Presentation）通常有"Free Cash Flow"的明细计算表，以此为准
2. 若公司无官方FCF定义，使用简化计算（OCF - Capex paid），并在报告中注明"简化口径，不扣除内容支付/租赁款等"
3. 两种口径差异 > 5% 时，必须在报告中同时列出两个数值并注明差异原因
4. **禁止将简化口径数值直接称为"公司FCF XXXX亿"**——应写"OCF-Capex paid约XXXX亿"或"官方FCF XXXX亿（含内容支付/租赁款扣除）"

**容易犯错的公司类型**：内容平台（腾讯/B站/爱奇艺：内容版权款大）、重资产+租赁密集型（零售/物流/酒店：租赁款大）

---

### 坑 9：监管处罚描述—多次独立事件混淆为一条（腾讯2026-05实例）

> 来源：腾讯2026-05-13深度分析，用户事后核验发现。

**现象**：将两次完全不同的监管事件压缩为"2021年反垄断罚款50亿整改已完成"——同时犯了3个错误：
1. **年份错误**：50万元罚款是2021年；29.9亿元罚款是2023年
2. **金额错误**：50亿元是虚构的，实际是50万元（音乐版权）和29.9亿元（财付通央行处罚），差了4个数量级
3. **事件合并**：两次性质完全不同的处罚被合并成一条

**正确记录格式**（腾讯实例）：

| 时间 | 处罚机构 | 被处罚主体 | 金额 | 处罚原因 | 状态 |
|---|---|---|---|---|---|
| 2021年7月 | 国家市场监督管理总局 | 腾讯音乐娱乐集团 | **50万元人民币** | 互联网音乐独家版权反垄断，要求解除独家授权 | 整改完成 |
| 2023年8月 | 中国人民银行 | 财付通支付科技有限公司 | **29.9亿元人民币** | 违反支付结算、反洗钱等相关规定 | 公告已整改，称对集团财务无重大影响 |

**根本原则**：
- 每次处罚独立一行，绝不合并
- 金额必须溯源原始公告（cninfo/港交所披露/监管机构官网），禁止依赖记忆
- 额度判断：若单次罚款 < 当年净利润1% → 轻微；1-5% → 一般；> 5% → 重大；> 20% 且影响核心业务 → 致命

### 坑 10：审计机构依赖历史惯例——双实例（茅台+太保，2026-05）

> 来源：贵州茅台、中国太保深度分析，用户事后核验发现。两份报告同犯此错。

**现象**：
- 贵州茅台：写成"毕马威华振"（曾经的长期审计机构），实际2025年报已换为**天健会计师事务所（特殊普通合伙）**
- 中国太保：写成"普华永道"，实际2025年报审计机构为**安永华明会计师事务所**

**根因**：AI依赖"该公司历史上一直是X审计"的记忆，而未查当年年报摘要。大公司更换审计机构不罕见（监管要求轮换、审计费竞争等），间隔1-2年就可能发生变化。

**正确做法**：审计机构必须从**当年年报官方摘要**中直接提取：
- 查巨潮资讯（cninfo.com.cn）当年年报摘要首页"会计师事务所"字段
- 或查上交所/深交所披露的年报摘要PDF，搜索"会计师事务所"或"审计机构"
- **任何情况下禁止依赖记忆或历史惯例**

**前置检查嵌入点**：在第0步前置检查中，审计机构应是第一个核实项，与审计意见类型一同记录：
```
审计机构：[从当年年报摘要提取]（来源：[年报摘要URL]）
审计意见：标准无保留意见 / [其他] → 若非标准无保留，触发一票否决
```

### 坑 11：评分汇总表与分项得分算术不一致（太保，2026-05）

> 来源：中国太保深度分析，用户事后核验发现。

**现象**：
- E维度正文分析中已有自校正注释"应为16分"（发现了原始填写错误）
- 但综合评分汇总表的E行仍显示14分，最终总分79分
- 实际应为：A9+B17+C13+D13+E16+F13 = **81分**（非79分）
- 公司页链接注释也跟着写了错误的79分

**根因**：修改分项得分时只更新了正文，遗漏了汇总表；或者在正文中写了"应为XX"的注释却没有同步落实到表格里。

**正确做法**：
1. 完成所有维度分析后，在汇总表填写时重新手工加总：A + B + C + D + E + F = 总分
2. 若正文任何位置有"应为X"/"原为X"/"修正为X"的注释，**立即**同步更新汇总表，不能留下"已知错误但未修正"的状态
3. 提交前执行算术验证：`Σ(各维度得分) == 汇总表总分`，一个字符都不能差

### 坑 12：业务分部增减速方向写反（茅台系列酒，2026-05）

> 来源：贵州茅台深度分析，用户事后核验发现。

**现象**：将茅台系列酒描述为"高单位数增长""明星业务"，实际2025年其他系列酒收入222.75亿，**同比-9.76%**（明显负增长）。BCG矩阵应为"问题"（而非"明星"）。

**根因**：
- 依赖"系列酒在过去几年一直增长"的历史印象，未核查最新年报数据
- 2025年系列酒主动收缩/降库调整，是行业深度调整的结果，与历史趋势完全相反
- 可能混淆了Q1 2026数据（+12.2%单季度反弹）与2025全年数据（-9.76%）

**正确做法**：
- 增减速方向是**最基础的数据准确性要求**，必须从当年年报分部收入表或利润表直接读取
- 若近期数据与历史趋势相反，这正是报告中值得特别点出的"转折信号"，不应掩盖
- 季度数据（如2026Q1单季）不能替代年度数据（2025全年），两者并列时需明确区分时间范围

**BCG矩阵填写规则补充**：
- 增速使用**最近完整财年（年报）**数据，而非单季或历史平均
- 若季度与年度方向相反，在BCG格子里注明："全年-X%（调整中），Q1+X%（反弹）"

### 坑 13：集团已独立/已剥离子公司混入上市主体分析（茅台/习酒，2026-05）

> 来源：贵州茅台深度分析，用户事后核验发现。

**现象**：在贵州茅台系列酒品牌列表中写入"习酒"，实际习酒（贵州习酒股份有限公司）已于2023年独立运营，不属于贵州茅台（600519.SH）上市主体的合并报表范围。

**根因**：习酒曾是茅台集团旗下品牌，长期与茅台关联，但资产划转剥离后不再并入上市公司。未核查合并报表范围，依赖"印象中属于茅台系"。

**正确做法**：
1. 分析前必须确认**上市公司合并报表范围**：查最近年报"合并范围变动"或"重要子公司列表"
2. 有以下信号时需特别核查：
   - 公司名下存在与知名品牌/子公司相关的独立上市/分拆新闻
   - 年报分部收入金额与历史印象出入较大（可能已剥离或并入新板块）
   - 曾有资产重组、股权划转、分拆上市的公告
3. 已独立的子公司**不得**出现在业务分部表（B1）或品牌列表中；若有历史关联，可在B1注释中说明"已剥离，不再并表"

### 坑 14：融资工具仅看增发/配股，遗漏可转债等潜在摊薄工具（太保，2026-05）

> 来源：中国太保深度分析，用户事后核验发现。

**现象**：报告写"近5年无重大股权融资（无增发/配股）"，实际2025年中国太保发行了**155.56亿港元零息H股可转债**（转股溢价率25%，资金用于保险主业及战略扩展）。属于潜在股权摊薄工具，不应在F2融资分析中略去。

**根因**：仅查A股市场的增发/配股公告，遗漏了H股市场的资本运作；且因"零息"和"溢价"使融资看起来"不像融资"而被过滤掉。

**正确做法**：F2融资核查必须覆盖以下所有工具：

| 工具类型 | 是否构成潜在摊薄 | 查询来源 |
|---|---|---|
| A股增发（含定增/公开增发）| ✅ 直接摊薄 | 巨潮资讯 / 理杏仁 measures |
| A股配股 | ✅ 直接摊薄 | 巨潮资讯 |
| 可转债（A股/H股）| ✅ 转股后摊薄 | 巨潮资讯 / 港交所披露 |
| H股增发 | ✅ 直接摊薄 | 港交所披露（HKEX披露易）|
| 优先股 | ✅ 转换后摊薄 | 巨潮资讯 |
| 股票期权/限制性股票激励 | ⚠️ 有限摊薄 | 股权激励方案公告 |

**报告表述标准**：
- ✅ 正确："近5年A股端无增发/配股；但2025年发行H股可转债155.56亿港元（零息，转股溢价率25%），存在远期转股潜在摊薄。"
- ❌ 错误："近5年无重大股权融资。"（遗漏可转债）

### 坑 15：审核修复 P1 问题后未触发评分联动——导致事实与评分脱节（绿的谐波，2026-05）

> 来源：绿的谐波深度分析，用户审核反馈发现。

**现象**：逻辑审核 agent 发现 F2 减持时间线叙述有误（"2023-2025年持续减持"→实为"2024年9月底部增持+2025年6-9月集中套现"）。事实修复已写入报告（新增月度分布表、底部增持背景），但 F 维度分数未重新评估，仍保留原始 8 分。这使报告出现"叙述已修正但评分仍反映修正前叙述"的内在矛盾。

**根因**：P1 修复流程只关注"把错误的文字改对"，没有在修复后显式走一遍"这个 P1 修复是否影响当时的打分逻辑"的闭环。

**正确做法（每个 P1 修复之后必须执行）**：

1. **明确写出评分影响判断**（不能跳过，即使最后结论是"分数不变"也要记录）：
   ```
   P1修复「减持时间线」后，评分联动检查：
   - 影响维度：F维度 → F2 子项「实控人行为」
   - 修正前叙述：2023年起系统性套现 → 扣-4分（持续多年看空信号）
   - 修正后事实：2024年9月底部增持 + 2025年6-9月集中套现
   - 重审判断：底部增持是真实正向信号，但规模仅占减持的1.2%；集中度（53%/单月）与持续性的扣分性质不同，整体负面程度稍有缓和
   - 决定：F2扣分从-4调整为-3 → F总分 8→9 → 全维度总分 66→67
   ```
2. **同步更新所有引用评分的位置**（缺一不可）：
   - 维度正文末尾的评分说明
   - 评分汇总表（维度行 + 总分行）
   - 总分算术自校验行
   - 综合结论的评级/档位段（若分数跨越档位边界则更新档位）
   - 公司页深度分析引用区块中的"评分：XX/100"
   - watchlist JSON 中的 `prebuy_conclusion`

3. **分数不变时也要记录**（留下审阅轨迹）：
   > P1修复「XXX」后评分联动检查：影响维度 → 综合判断后分数维持 X 分不变，原因：[原因]。

**附：P1 修复 → 评分影响速查表（高频情形）**：

| P1 修复类型 | 最可能影响的维度 | 分数变化方向 |
|---|---|---|
| 减持时间线描述错误（夸大持续性）| F维度 F2 | 可能降低扣分（上调）|
| 减持金额高估/低估 | F维度 F2 | 按比例调整 |
| 业务增速方向写反（正→负）| B维度 B1-B2 + D维度 D4 | 下调 |
| 审计机构非标（原写标准）| F维度 F4 → **触发一票否决** | 取消分析 |
| 融资工具遗漏（高度摊薄）| F维度 F2 + E维度 E5 | 下调 |
| 监管处罚低估（金额/次数）| F维度 F4 + D维度 | 下调 |
| OCF 计算口径错误（实测与报告偏差 > 10%）| E维度 E2 | 按修正值重算 |

**底线原则**：**任何 P1 修复，都必须走完"修复事实 → 评价分数影响 → 决定是否调分 → 更新所有引用"完整闭环，不允许只修复文字不检查分数。**

### 坑 16：OCF 口径混用——母公司报表 vs 合并报表（海康威视，2026-05）

> 来源：海康威视深度分析，用户事后核验发现。这是 E2 现金流质量分析中最严重的口径错误。

**现象**：报告将海康威视2020-2024年OCF写为约74.75/84.90/65.55/83.98/64.35亿，净现比约50-60%，并据此得出"净现比陷阱"警示。
**实际情况**（合并报表口径）：

| 年份 | 归母净利（亿）| OCF合并（亿）| 净现比 |
|---|---|---|---|
| 2020 | 133.9 | 160.88 | 120% |
| 2021 | 168.0 | 127.09 | 76% |
| 2022 | 128.4 | 101.64 | 79% |
| 2023 | 141.1 | ~166.22 | ~118% |
| 2024 | 119.8 | 132.64 | 111% |
| 2025 | 141.95 | 253.39 | 178% |

报告中使用的64.35亿是**母公司报表**（仅含持有子公司股权的母体，不含子公司经营现金流），与**合并报表**的132.64亿相差一倍。结论方向完全反转。

**根因**：从东方财富或其他数据源获取OCF时，没有区分数据属于"母公司报表"还是"合并报表"；对于有大量子公司的集团企业（如海康），两者差异极大。

**正确做法**：
1. **永远使用合并报表OCF**——除非分析目的是评估母公司单体（极少见）
2. 用东方财富 API 验证时，`MGJYXJJE` 字段来自合并报表，是正确口径
3. 若手动从年报PDF提取：只读"合并现金流量表"，不读"母公司现金流量表"（后者是年报后半部分的附表）
4. **快速核验**：若计算出的净现比远低于行业惯例（如制造业龙头常年<60%），应立即怀疑口径是否是母公司报表，用东方财富复核

**检查要点（E2节前必读）**：
> "我使用的OCF数据，是合并报表还是母公司报表？"——对集团型企业，这个问题必须在E2开始前明确回答。

### 坑 17：管理层信息依赖陈旧记忆（海康威视，2026-05）

> 来源：海康威视深度分析，用户事后核验发现。与坑10（审计机构）同类性质，但发生在管理层信息上。

**现象**：报告写"董事长陈宗年、CEO胡扬忠"，实际：
- 董事长：**胡扬忠**（非陈宗年；陈宗年已卸任）
- 总经理：**徐鹏**（非胡扬忠；胡扬忠已升任董事长）

**根因**：依赖"海康一直是陈宗年领导"的历史记忆，未核查最新年报。与审计机构轮换类似，董事长/总经理的变动可能发生在任意年份，不能假设"历史上是谁就一直是谁"。

**正确做法**：
1. F1节管理层信息**必须从最近年报摘要或业绩说明会公告**中提取：
   - 巨潮资讯年报摘要首页"董事会"/"高级管理人员"部分
   - 或业绩说明会参会人员公告（通常列出现任董事长+总经理+CFO）
2. 职位名称注意区分：A股常用"总经理"，而非"CEO"；港股/外资企业常用"CEO"。报告中应与年报口径一致
3. 凡写到"现任XXX为XX"，必须注明来源年份：如"（2024年报）"

**前置检查嵌入点**（与坑10审计机构同步核查）：
```
管理层（来源：[年报摘要URL]，[年份]年报）：
- 董事长：[姓名]
- 总经理/CEO：[姓名]
- CFO：[姓名]（如有独立CFO）
```

### 坑 18：高管被查/腐败事件淡化为"正常人事调整"（茅台，2026-05）

> 来源：贵州茅台 2026-05-24 深度分析，外部审核发现。

**现象**：茅台 F1 维度将蒋焰（原CFO兼董秘）被调查事件描述为"正常国企人事调整"，F1 得分 4/5，综合结论称"治理结构稳健"。外部审核指出蒋焰事件不能归类为正常轮岗——CFO兼董秘被查是治理风险信号。

**实际情况**（来源：5月15日版深度分析 + 公开报道）：
- 袁仁国（原董事长）：2019年被调查，2021年以受贿罪被判无期徒刑
- 高卫东（原董事长）：2023年被调查
- 杜光义（原副总经理）：2019年被调查
- 蒋焰（原CFO兼董秘）：2026年3月被调查

近10年茅台已有多名高管被查，属于周期性系统性问题，而非个别偶发事件。

**根因**：F1 原有的"管理层稳定性"分析框架只看任职年限和离职率，缺少"高管廉洁历史"维度。当腐败事件出现在前任而非现任时，容易被"那是过去的事了"或"正常轮岗"的思维框架过滤掉。

**正确做法**：
1. F1 必须包含高管廉洁历史检查（见 F1 章节 🆕 新增项）
2. 逐人逐条记录被查高管，不得合并描述
3. 区分：
   - ✅ "2025年董事长和CFO同时发生变更，属于正常国企轮岗" → 这是对职位变动的描述，可能合理
   - ❌ "蒋焰被调查属于正常人事调整" → 把腐败淡化为轮岗，错误
   - ✅ 正确表述："2025年管理层发生变动（张德芹→陈华董事长、蒋焰→余思明CFO）。其中蒋焰（原CFO兼董秘）于2026年3月被调查，属治理风险信号；同时茅台历史上袁仁国、高卫东等多任高管曾被查处，F1 须扣分。"

**判断标准**：
- 高管被查（调查/逮捕/判刑）≠ 正常离职/退休/轮岗，不可混用
- 周期性高管腐败（近10年≥2人）→ F1 系统性扣分
- 现任核心高管正在被调查 → 触发黄旗，F1 扣分且综合风险地图须列为治理风险

**附：F1 廉洁扣分速查**

| 廉洁记录 | F1 扣分 | 说明 |
|---------|---------|------|
| 近10年无高管被查记录 | 不扣分 | |
| 有个别高管被查但已处置完毕，现任班子干净 | **-1** | 如仅1人且非现任 |
| 周期性高管腐败（近10年≥2人，含历任董事长）| **-2** | **茅台适用此项** |
| 现任核心高管（董事长/CEO/CFO）正在被调查 | **-3 且触发黄旗** | 一票否决级 |
