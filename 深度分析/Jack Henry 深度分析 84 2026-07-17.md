# Jack Henry 深度分析

> [!summary] 核心结论
> **公司质量84/100。** Jack Henry 是美国社区及区域银行、信用合作社的关键技术基础设施供应商，优势来自核心系统高转移成本、监管与数据复杂性、长期客户关系及开放式产品生态。它不是高速SaaS：收入中位数个位数增长，现代化需要持续资本化开发投入，银行并购会带来deconversion；但现金流、ROIC、低SBC和资产负债表均达到高质量标准。

## A. 历史基因与公司DNA（9/10）

### A1. 起源

公司1976年在密苏里州创立，从小型银行核心数据处理软件起步。其先天基因是“长期服务金融机构关键账务系统”，需要可靠性、合规和服务文化，而非流量营销。

### A2. 控制权稳定性

- 无控股股东或家族控制。
- 历任CEO多为内部长期培养，2024年Adelson接替Foss。
- 董事会多数独立并设独立Lead Director。

### A3. 资本运作

- 历史并购集中在支付、数字银行、欺诈、数据和补充产品。
- FY2025无新增商誉；商誉约8.05亿美元，主要分布于Core、Payments和Complementary。
- FY2026前九个月收购支出4,239万美元，规模可控。
- 未见卖资产维持经常利润模式；FY2026资产出售收益单独调整。

## B. 商业模式质量（17/20）

### B0. 创立期与当下商业模式画布

| 要素 | 创立初期 | 当下 |
|---|---|---|
| 客户 | 小型银行 | 社区/区域银行、信用合作社和非核心客户 |
| 价值 | 自动化账务处理 | 核心、支付、数字、风控与开放集成 |
| 渠道 | 直销与本地安装 | 直销、private/public cloud、伙伴生态 |
| 关系 | 软件许可与维护 | 多年处理、托管和订阅关系 |
| 收入 | 软件、硬件、维护 | 服务支持57%、处理43%（FY26 Q3） |
| 资源 | 银行软件和服务人员 | 数据、连接、合规、平台、客户信任 |
| 活动 | 部署与维护核心系统 | 托管、处理、研发、支付与数字运营 |
| 伙伴 | 硬件商 | 约束严格的第三方fintech与技术商 |
| 成本 | 人员与硬件 | 人才、数据中心、软件开发和摊销 |

- 不是重资产制造，但也不是近零投入软件；核心系统迁移和托管需要长期实施。
- 模式从本地许可转向云托管与处理，提高经常性收入和客户粘性。
- 分类：**高转移成本、经常性收入、资本化研发较高的金融基础设施软件服务型**。

### B2. 盈利机制

- 核心托管、处理和维护具有高复购；转换核心系统成本高、周期可达多年。
- 支付收入随交易量增长，较核心收入更有宏观和费率敏感性。
- 补充产品可向已有核心客户交叉销售，也能独立销售给非核心客户。
- 规模效应中强：平台和合规投入可跨客户复用，但客户上线、支持和数据中心仍有边际成本。

### B3. 定价权

| 来源 | 强度 | 依据 |
|---|---|---|
| 品牌/信任 | 强 | 50年服务关键银行系统 |
| 转移成本 | 强 | 数据迁移、合规、员工培训、业务中断风险 |
| 网络效应 | 弱至中 | 支付连接和生态有网络效应，核心软件本身较弱 |
| 监管资质 | 中强 | 银行审查、SOC控制和数据安全要求 |
| 成本领先 | 中 | 规模摊薄研发和合规 |
| 开放集成 | 中强 | 支持第三方fintech降低客户被封闭生态锁死的顾虑 |

综合定价权中强。deconversion收入会暂时提高GAAP增长，不代表可持续提价。

### B4. 可持续性

- 美国社区银行和信用合作社仍需与大型银行及新金融科技竞争，IT支出具长期必要性。
- 行业并购减少客户数量，并带来deconversion风险。
- public cloud-native现代化可赢得替换订单，也需承受多年双栈开发成本。
- FY2026 Q3的17个竞争性core wins是正面信号，但上线节奏和合同价值未披露。

## C. 竞争格局与护城河（17/20）

### C1. 市场地位

核心银行系统主要面对Fiserv、FIS、CSI、Finastra等竞争；数字与支付面对更多专业fintech。公司未披露统一可比市占率，本报告不编造CR5。约950家银行核心客户、715家信用合作社核心客户证明其处于美国市场第一梯队。

### C2. 产业链话语权

| 维度 | 结论 | 依据 |
|---|---|---|
| 成本传导 | 中强 | FY2025各主要分部成本率改善约1pct |
| 需求传导 | 慢 | 核心销售到上线跨多个季度；支付量当期反映 |

| 综合议价 | “吃肉偏稳” | 高转换成本，但大型银行客户仍可议价 |

### C3. 横向竞争

- Fiserv/FIS规模更大、产品更广。
- 新fintech在单点数字体验、支付和数据产品上更灵活。
- Jack Henry以社区金融机构专注、服务文化和开放集成差异化。
- public cloud转型能否避免传统核心系统技术债是关键。

## D. 战略清晰度与执行力（12/15）

### D1. 战略主线

1. 维护并现代化核心系统。
2. 从private cloud向public cloud-native增加选择。
3. 以digital、faster payments和补充产品交叉销售。
4. 保持开放生态，允许第三方fintech接入。
5. 用稳定现金流支持研发、分红和回购。

### D2. 执行验证

- FY2025剔除deconversion后Core/Payments/Complementary均增长6%以上。
- FY2026前九个月调整后收入+7.6%、调整后营业利润+16.7%。
- public/private cloud收入+8.9%、digital/transaction +12.8%、faster payments +50.5%。
- 资本化软件开发继续上升，说明战略投入大；但未披露public cloud迁移客户数和单独ROIC。

### D3. PESTEL与价值链

- 监管提高进入壁垒，也提高合规和网络安全成本。
- 银行并购减少潜在客户，数字竞争提高剩余客户IT需求。
- 最大价值环节是核心账务数据、支付处理、可靠托管和开放集成；硬件转售价值最低。
- AI可提高客户服务和欺诈识别，也增加模型治理与数据风险。

- 截至2026-03-31 TTM净利润5.192亿美元，平均权益20.856亿美元，ROE 24.9%。

- 资本化产品软件1.400亿美元是现金支出，不能因其未进入当期R&D费用而忽略。
- FY2026前九个月OCF同比大增，部分来自递延税等非现金与营运资本差异，不应简单年化。

### E4. 资本结构与资产质量

- FY2025 SBC 2,839万美元，占收入1.2%，净稀释风险低。
- 应收账款FY2026 Q3同比基本持平，而九个月收入增长8%，收款质量良好。
