# A股未收录高分企业筛查（cn-high-score-discovery）

## 定位

参考 `.claude/skills/cn-quality-mispricing-screen`（错杀A股，看价格/跌幅/估值，需定期跑），本 skill 反过来：
**完全不看当前股价**，只从「企业质量能否支撑 B_GROWTH/A_CORE 级（深分≥70/76 + 管档≥70/76）」角度，
粗排出尚未被本知识库深度覆盖、但大概率够高分的 A股公司，作为未来开「全面分析（三件套）」的上游候选清单。

- **去掉时间/价格因素** → 公司基本面变慢 → **不需要定期跑**（几个月甚至半年刷一次池即可）。
- 正因没有时间衰减，**一次建池会产出非常多** —— 因此产物设计成**持久候选池 + 分批复核**，而不是一次性报告。
- 本 skill 只做「谁值得开三件套」的粗筛与排队，**不写 watchlist、不自动开三件套**（同错杀 skill 的上游定位）。

## 覆盖口径（宽松）

- **硬排除**：已在 watchlist(strategic/core/growth/out_of_scope) + 已进 `00-首页/低分公司登记.md`（曾判低分）。
- **只打标不排除**：有 `01-公司` 页 / `深度分析` / `管理层档案` 旧研究的**仍纳入**池，行内打「覆盖」标签
  （如 `公司页/深度分析/管理层档案`），Run B 复核时据此选择「跳过(旧研究已够) / 更新 / 新开」。
- 池里的行标 `全新` = 本知识库从未碰过，是最有价值的复核对象。

## 核心机制：为什么这样解决「一次结果太多」

- **大列表本身是数据资产**（`data/screens/A股高分候选池.json`），不是一次性报告 → 不必一次读完。
- 输出体量拆成两个独立旋钮：
  - **池规模** = f(市值下限 + 质量分阈值 + 覆盖口径) → 只决定池文件多大；
  - **单次报告大小** = 恒定复核批 N（默认 5~8 家）→ 由每次 Run B 决定，与市场宽松度无关。
- 全市场逐只拉财务（理杏仁 fs ~2000 次）只在 **Run A 建/刷池** 时发生一次；Run B 的 API+token 成本恒定小。
- Run B 反复几次即可把池头逐步消化，每次对话输出都小、可用。

## 池文件

| 文件 | 作用 |
|---|---|
| `data/screens/A股高分候选池.json` | **状态源**。每行：代码/简称/板块/质量分/池内档位/财务快照/审计意见/管理层红旗/覆盖标签 + `review_status`/`reviewed_date`/`notes`/`进入池日期` |
| `data/screens/A股高分候选池_YYYY-MM-DD.csv` | 每次 Run A 导出的可读快照（Excel 用） |

`review_status` 取值：`pending`（待复核，默认）→ `recommended`（已建议开三件套）/ `reviewed`（看过未推）/ `skip`（旧研究已覆盖跳过）/ `drop`（红旗排除）。

## Run A：建池 / 刷池（少跑，仅在池过期或要扩大覆盖时）

```bash
# 建/刷池（今天；会自动回退到最近交易日）
python scripts/cn_high_score_pool.py --date 2026-09-04

# 常用参数
--min-cap 50     # 流通市值下限(亿)，越大池越小
--min-score 60   # 质量分入池下限（≥70 Ⅰ候选 / 60-70 Ⅱ候选）
--codes 600276,600809   # 只对指定代码跑(测试用)
--limit 300       # 只对市值 top 300 跑(测试/快速预览)
--skip-hot        # 跳过管理层红旗批量(调试)
```

- 脚本每次**保留旧池的 review 进度**（按代码合并 `review_status`/`notes`），不会因刷新丢失已复核行。
- 刷池频率建议：财报季后或半年一次即可；不需要周期跑。
- Run A 完成后，脚本终端会打印 Ⅰ候选 top 清单与池分布，供你决定是否立刻进 Run B。

## Run B：分批复核（本 skill 每次被调用的实际动作）

> 每次调用默认只精筛 **池头未复核的 5~8 家**（Ⅰ候选优先；Ⅰ清完再进 Ⅱ），不要把整池铺开。

1. **取批**：读 `data/screens/A股高分候选池.json`，取 `review_status=pending` 且质量分最高者 N 家
   （Ⅰ候选优先；同分时优先「全新」>「有旧研究」）。
2. **逐家精筛**（每家的动作，成本可控）：
   - 读池内财务快照（10Y ROE/毛利/净利/FCF/分红率/股本）→ 判断质量分是否可信；
   - **红旗命中**（`管理层红旗` 非「无」）才下钻 CNINFO 明细：`executive_trades`/`share_pledge`/
     `company_penalties`/`company_lawsuits`（复用 `scripts/cninfo_api.py` 封装）；边界才用 Tavily；
   - `覆盖` 含旧研究 → 判定「跳过(旧研究已够)/更新」；`全新` → 认真评估是否值得三件套；
   - 补一眼商业模式/护城河（AI 基于公司名称+指标推断，必要时一条 WebSearch，不展开三件套）。
3. **给判定**：**建议开三件套**（预估深分+管档双双≥70，即大概率 B_GROWTH 级）/ **疑点需深挖** / **排除(红旗)**。
4. **写回**（主 Agent 写，子 Agent 不得直接写文件）：把本批每家 `review_status`/`reviewed_date`/`notes`
   写回池 JSON。
5. **对话输出**：每家的「一眼印象 + 判定」小表 + 强推 2~3 家「建议全面分析 XXX」。
   本 skill 不写 watchlist；被推荐公司由用户自行触发「全面分析 XXX」或塞进待办队列。

## 管理层角度怎么处理（红旗层，诚实不给假分数）

全池不可能逐家做定性管档 → 只用廉价信号打红旗带：

| 信号 | 来源 | 阈值(WATCH) |
|---|---|---|
| 股权质押占总股本 | 理杏仁 `hot/ple` 的 `ps_sc_r` | >10% |
| 大股东近1年净减持 | `hot/mssc` 的 `mssc_cap_rc_y1` | < -0.5% |
| 高管近1年净减持 | `hot/esc` 的 `esc_cap_rc_y1` | < -0.5% |
| 非标审计 | 理杏仁 fs 响应 `auditOpinionType`（近端） | 非 `unqualified_opinion` → **直接剔除**（repo 红线） |
| 分红融资比 `dfr_fs` | `hot/df` | 仅展示列，不据此罚分（避免误伤年轻/低分红好公司） |

任何一家被标红旗 ≠ 定论，Run B 复核时用 CNINFO/Tavily 二次确认。资料缺失不惩罚（可得性 ≠ 公司质量）。

## 企业质量分口径（脚本 `quality_score`）

**五维 100 分制，权重：成长25 + 盈利25 + 现金流25 + 资本15 + 股本与股东回报10 − 异常惩罚**（无估值维度）：

- 成长：营收/净利 5Y/3Y CAGR + 跨期一致性
- 盈利（核心）：**10Y ROE 均值** + **10Y 最差年 ROE**（可持续性）+ 毛利率地板
- 现金流：OCF 趋势 + 近5年累计 FCF 为正/转化率 + FCF 正年数 + 应收剪刀差 + 净利率
- 资本：ROA、负债率、利息覆盖、债务权益比
- 股本与股东回报：股本膨胀（少稀释）+ 近5年分红率

惩罚项：增速异常、利润增速脱节、ROE>40%、应收>营收、OCF 3Y 为负、5Y FCF 累计为负、股数膨胀>2%、OCF 负年数≥3。

入池档位：质量分 ≥70 → **Ⅰ候选**（质量上大概率 A_CORE 级）；60–70 → **Ⅱ候选**（B 级）；<60 不入池。

> 校准记录（2026-09-04 全量首跑）：`--min-cap 50 --min-score 60` 下 Ⅰ候选 35 家 / Ⅱ候选 94 家 / 全新 92 家，
> 分布健康、头部为合理高质量标的，阈值与 min-cap 默认值保留。可用 `--min-cap`/`--min-score` 调池大小。

> 分数 = 粗排工具，近似深分 E 维度，绝不等于真深分。管理层维度此处只有红旗带，最终以三件套为准。

## 注意事项

1. **金融股缺失**：理杏仁 `fs/non_financial` 不服务银行/券商/保险 → 它们无数据自动不入池（与错杀 skill 一致）。如要覆盖金融后续扩展 `fs/{bank|security|insurance|other_financial}`，首版不做。
2. **刷新保留进度**：脚本按代码合并旧 `review_status`，重刷不丢已复核结论。
3. **API 用量**：Run A 全量 ≈ 55 次 fundamental + ~2000 次 fs + 少量 hot 批（理杏仁自动记入 `data/api_usage/`，按 ¥1800/年计费）。这是本 skill 最大的单次开销，只应在建/刷池时发生；Run B 复核批成本极小。运行 Run A 前可先用 `--limit` 或 `--codes` 预览。
4. **北交所/微盘**：市值门槛已排除绝大多数；`--min-cap` 是控制池大小第一旋钮。
5. **A+H/名称**：覆盖标签用 CNINFO `zwjc` 简称 glob 顶层目录匹配；极少数页面文件名与证券简称不一致时可能漏标，Run B 复核前可 `grep 01-公司/ 公司名` 兜底。
6. **校准**：首次全量建池后，据真实质量分分布回填 Ⅰ/Ⅱ 阈值与 `--min-cap` 默认值。

## 与三件套的关系

本 skill 是**上游候选清单生成器**。Run B 推荐的公司 → 用户触发「全面分析 XXX」（或并入待办队列）开三件套；
三件套完成后由主流程按 WATCHLIST_RULES 定档。保持职责边界：本 skill 不写 watchlist、不自动开三件套。
