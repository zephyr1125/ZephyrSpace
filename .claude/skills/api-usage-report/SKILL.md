# API 用量统计报告

## 触发条件

用户说以下任一触发词时执行本 SOP：
- API用量 / API报告 / API使用情况 / API利用率
- 续约评估 / API续约
- api usage / api report

---

## 第 1 步：确定报告类型

识别用户意图：

| 用户表述 | 报告类型 | 脚本参数 |
|---------|---------|---------|
| "API用量" / "本月用量" / 无时间修饰 | **月度汇总** | `--month YYYY-MM`（默认本月） |
| "最近N个月" / "这半年" / 含时间范围 | **趋势报告** | `--months N` |
| "续约" / "年度" / "要不要续" | **续约推荐表** | `--renewal` |

---

## 第 2 步：执行脚本

```powershell
# 月度汇总（默认本月）
python scripts/api_usage_report.py

# 指定月份
python scripts/api_usage_report.py --month 2026-08

# 最近 N 个月趋势
python scripts/api_usage_report.py --months 6

# 续约推荐表（所有历史数据）
python scripts/api_usage_report.py --renewal
```

---

## 第 3 步：解读与呈现

脚本输出分两种格式：

### 月度报告解读要点
1. **分析次数与类型分布** — 这个月跑了多少次分析、哪些类型
2. **各 API 调用量** — 与上月对比（如有上月数据，手动对比 `data/api_usage/上个月/` 下的文件数）
3. **成功率异常** — 任一 API 成功率 < 90% 应标注排查

### 续约推荐表解读要点
1. **付费 API 逐项评估** — 目前只有智堡（¥2000）和理杏仁（¥1800）
2. **调用量 vs 费用** — 判断"每次分析成本"是否合理
3. **不可替代性** — 如果某个 API 的独有功能完全没有被使用，建议降级或取消

---

## 第 4 步：输出格式

如果是**续约报告**，输出结构化表格：

```markdown
## API 续约评估（截至 YYYY-MM）

| API | 年费 | 总调用 | 覆盖分析 | 成功率 | 续约建议 |
|-----|------|--------|---------|--------|---------|
| 智堡 Wisburg | ¥2,000 | N次 | 深度分析N次/管理层N次 | 99% | ✅/⚠️/❌ |
| 理杏仁 Lixinger | ¥1,800 | N次 | ... | 99% | ✅/⚠️/❌ |
| Tavily | 免费 | N次 | ... | 99% | 🆓 用量安全/⚠️ 接近限额 |

**关键发现**：
- [最重要的1-3条发现]

**续约建议**：
- 智堡：[续/不续] — [理由，1-2句]
- 理杏仁：[续/不续] — [理由，1-2句]
```

如果是**月度报告**，直接呈现脚本输出的汇总+Top端点明细即可。

---

## 注意事项

1. **脚本无输出 = 暂无数据**：如果脚本输出"暂无 API 用量数据"，说明 `data/api_usage/` 下还没有 run 日志。告知用户等跑几次分析后再来看。
2. **数据质量**：追踪系统 2026-08-06 上线，此前的分析没有记录。
3. **不追踪 Claude 内建工具**：WebSearch/WebFetch/MCP 含在 Claude 订阅中，非独立付费，不在报告中。
4. **Tavily 额度预警**：月调用 > 800 次时提醒用户注意免费额度边界。
5. **Tushare 淘汰追踪**：如果连续 3 个月 Tushare 调用为 0，提示用户可确认淘汰。
