# A股质量与错杀候选筛选

目标是发现值得进一步研究的新公司。低PE和大回撤只是筛选线索，不能直接证明错杀。

## Watchlist 排除规则

- 开始筛选时读取工作区 `data/watchlist_core.json`、`data/watchlist_growth.json` 的 `entries`，以股票代码匹配，不依赖公司名称。
- 使用 `scripts/cn_mispricing_screen.py` 的 `_load_watchlist_cn(universe)`，必须传入本轮全A公司代码及名称清单。除A股代码外，还将所有市场Watchlist公司名与A股公司主体匹配；同一公司以港股入池也排除其A股，例如 `09980.HK 东鹏饮料` 排除 `605499.SH`。名称不一致时核查官方主体和A/H映射，不能只按证券代码排除，也不能模糊匹配母子公司。
- 已在任一档位的公司均从新候选池、二筛排序、重点推荐及下一批研究名单中排除，与 trackingStatus、评分和估值无关。仅在排除统计或底稿中留存。
- Watchlist 缺失、解析失败或结构异常时停止候选发布，修复读取问题后再继续；不得将读取失败视为空池。
- 复用历史筛选底稿或临时运行脚本时同样必须执行排除，不得只依赖命令行参数。交付前重新读取当前两档文件，断言最终候选代码与排除集合交集为空，报告排除数量。
- 已入池公司的更新与调仓属于其他任务；仅用户明确指定复核已入池公司时，才单独处理。

## 筛选与交付

读取 `lixinger-query` 技能获取最新可用数据，注明行情日期，验证年报和最新财报期别。参考工作区最近一轮 `data/screens/cn-quality-*/` 底稿与个人观察报告中的质量、估值及现金流条件，保留可复核原始数据。

`scripts/cn_mispricing_screen.py` 默认排除Watchlist；其旧评分只是代理指标。使用前需核查缺失数据放行和未复权回撤问题，不把旧脚本输出直接当最终名单。回撤使用前复权价格及明确窗口，短上市历史单列；金融行业使用独立模型，资源周期公司不与普通经营公司混排。

对优先候选核查最新业绩、跌价原因、治理和反证条件。仅产出筛选观察，不自动扩展为完整三件套，不写入或同步Watchlist。笔记保存至现有 `99-个人观察/`，注明“未完成完整三件套”。
