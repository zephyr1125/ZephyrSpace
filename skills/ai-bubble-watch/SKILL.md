# AI 泡沫破裂仪表盘（周度打分）

## 定位

回答一个问题：**这周，AI 泡沫离破裂更近了还是更远了？**

不是预测精确日期（不可能），而是把 8 个**先行指标**量化成一个可跟踪的分数，
让"该不该提前减仓"变成**数据驱动**而非情绪驱动。

> ⚠️ 核心理念：**动量 > 绝对值。** 单周指数从 20 跳到 40，比一直停在 50 更危险。
> 真正的扳机是"第一家大厂砍 capex"或"OpenAI 募资翻车"——这两个亮红灯，无视总分直接升级。

运行频率：**每周末一次**（周六/周日）。

---

## 8 个指标与权重

| ID | 指标 | 档 | 权重 | 频率 |
|----|------|----|----|------|
| **R1** | 超大厂在财报里"砍"或"含糊化" capex 指引（下修绝对额，非放缓增速） | 🔴 | ×2 | 低·季度 |
| **R2** | OpenAI/Anthropic/xAI 某轮融资募不满 / 估值平轮或下折 | 🔴 | ×2 | 高 |
| **R3** | 二手 H100/A100 租赁价断崖（旧卡贬值坐实） | 🔴 | ×2 | 高 |
| **R4** | 数据中心私募信贷利差走阔 / 首例 SPV 违约 | 🔴 | ×2 | 高 |
| **Y1** | NVIDIA 数据中心收入环比首次零增长或下滑 | 🟡 | ×1 | 低·季度 |
| **Y2** | Neocloud（CoreWeave 等）客户集中度爆雷 / 取消订单 | 🟡 | ×1 | 高 |
| **Y3** | 循环交易占比上升（财报附注里"关联/投资对象贡献收入"变大） | 🟡 | ×1 | 低·季度 |
| **Y4** | 消费电子因AI挤出而提价（AI基建→HBM挤占DRAM产能→内存涨价→手机/PC/游戏机被迫提价） | 🟡 | ×1 | 高 |

**频率说明**：
- **高频指标**（R2/R3/R4/Y2）：几乎每周都可能有新信号 → 每周必查。
- **低频指标**（R1/Y1/Y3）：主要在**财报季**更新（约每年 1月底/4月底/7月底/10月底）。
  非财报季无新数据时 → **沿用上期分数**，并在报告里标「(沿用)」。
  财报季临近（扫描日处于上述月份）→ 提醒用户重点核查这三项。

## 打分标准（每项 0 / 1 / 2）

通用语义：**0 = 🟢 正常（无信号）｜1 = 🟡 预警（苗头/传闻/边际恶化）｜2 = 🔴 触发（确认）**

| 指标 | 0（🟢正常） | 1（🟡预警） | 2（🔴触发） |
|------|-----------|-----------|-----------|
| **R1** capex 指引 | 最近一季全部维持或上修 | 任一公司措辞转谨慎/暗示见顶/增速大幅放缓 | 任一公司明确**下修绝对额** capex 或削减 AI 支出 |
| **R2** 大模型融资 | 新一轮顺利/超额认购/估值上行 | 募资周期拉长/平轮传闻/领投方退出传闻 | 募不满 / 明确**下折(down round)** / 重要轮次推迟取消 |
| **R3** GPU 租赁价 | 新旧卡价格稳定或上行 | 上一代(A100/H100)环比跌 15–30% 或闲置率上升 | 断崖(环比 >30%) 或大面积闲置/退租 |
| **R4** 私募信贷/SPV | 利差平稳、发行顺畅 | 利差走阔/评级展望下调/发行遇冷 | **首例实质违约** / 重大发行失败 / SPV 重组 |
| **Y1** NVIDIA DC 环比 | 环比增长 >10% | 环比增长 0–10%（明显减速） | 环比零增长或下滑 |
| **Y2** Neocloud | 无异常 | 集中度风险被点名/小客户流失 | 大客户取消缩减 / Neocloud 财务困境 |
| **Y3** 循环交易 | 无新增/平稳 | 占比上升被分析师点名讨论 | 监管/审计关注 或 循环规模显著跳升坐实 |

**置信度**：每项标注证据强度。若证据不足以判断 → 取保守分（倾向给 1 而非 0，"宁可多报"），并标「需进一步核实」。

## 计算与等级

```
加权分 = Σ(R 指标得分 × 2) + Σ(Y 指标得分 × 1)  （2026-06-27 起 Y 从3项扩至4项）
满分   = (2+2+2+2)×2 + (2+2+2+2)×1 = 24  （2026-06-27 起从22扩至24）
破裂临近指数 = round(加权分 / 22 × 100)   # 0–100，越高越接近破裂
ΔWoW = 本期指数 − 上期指数               # 从总账读上期
```

| 指数 | 等级 | 含义 |
|------|------|------|
| 0–15 | 🟢 绿灯·派对继续 | 体系稳定，无可见裂缝。风险偏好可维持 |
| 16–35 | 🟡 黄灯·初现裂缝 | 裂缝浮现但尚未触发硬信号。需要收紧警戒 |
| 36–55 | 🟠 橙灯·风险显著 | 裂缝扩大，单点故障可能引发链式反应 |
| 56–75 | 🔴 红灯·加速恶化 | 多个硬信号触发，泡沫可能已在破裂 |
| 76–100 | ⬛ 深红·破裂进行中 | 避险资产为王，风险资产全面承压 |

### 硬触发规则（覆盖总分）

> 这两条**优先于**上面的指数→等级映射，因为它们是最强的破裂信号：
1. **任一 R 指标 = 🔴(2) → 等级至少升到 🟠 橙灯**（即使总指数还低）。
2. **≥2 个 R 指标 = 🔴(2) → 直接 🔴 红灯**。
3. **ΔWoW ≥ +15（单周）→ 即使绝对值不高，也要在报告开头标「⚠️加速恶化」**，并把建议等级上调一档。

## 执行流程

### 第 1 步：抓取证据（脚本）

```powershell
# 全量 7 指标
python scripts/ai_bubble_scan.py

# 周中只快查高频项
python scripts/ai_bubble_scan.py --only R2,R3,R4,Y2

# 指定日期
python scripts/ai_bubble_scan.py --date 2026-06-27
```

输出：`scripts/_ai_bubble_scan/YYYY-MM-DD.json`（每指标的最近新闻证据）。

### 第 2 步：AI 逐项核查与打分

1. 读 `scripts/_ai_bubble_scan/YYYY-MM-DD.json`。
2. **逐项判断**，证据不足或需要时效性更强的数据时，用 `WebSearch` 现场补搜（尤其 R3 GPU 租赁价、R4 利差、R1/Y1 财报数据）。
3. **低频指标处理**：读总账上期分数。若本期非财报季且无新证据 → 沿用上期，标「(沿用)」。若财报季有新数据 → 重新打分。
4. 每项给 0/1/2 + 一句证据摘要 + 置信度。**必须列出支撑打分的具体新闻标题 + 原文 URL**（这些将填入报告「证据明细」节）。
5. 按公式算加权分、指数、ΔWoW（从总账读上期指数）。
6. **应用硬触发规则**，确定最终等级。

**取数来源提示**（补搜时优先）：
- R1：各厂财报电话会 transcript、Reuters/Bloomberg/CNBC、SemiAnalysis
- R2：The Information、Bloomberg、Reuters、TechCrunch
- Y4：Al Jazeera、CNBC、IDC、TrendForce DRAM 报价、厂商官方公告
- R3：vast.ai / RunPod / SF Compute 报价、SemiAnalysis ClusterMAX
- R4：Bloomberg、FT、S&P/Moody's 评级动作
- Y1：NVIDIA 季报（约 2月底/5月底/8月底/11月底）
- Y2：CoreWeave/Nebius 财报与新闻、客户集中度报道
- Y3：FT、The Information、卖方 vendor-financing 专题、10-Q 附注

### 第 3 步：写周度报告 + 追加总账

**A. 周度详情** → `02-主题/AI泡沫监测/YYYY-MM-DD.md`（模板见下）。

**B. 追加总账一行** → `02-主题/AI泡沫监测/_仪表盘总账.md`（趋势表，不覆盖历史）。

### 第 4 步：向用户输出结论

简报形式：**指数 + 等级 + ΔWoW + 本周该做什么**。若触发硬规则或加速恶化，开头醒目标注。

## 原则

1. **动量优先。** 报告永远突出 ΔWoW 和趋势，不要只报一个孤立分数。
2. **宁可多报。** 边界模糊倾向给 1 不给 0；硬触发宁愿误报也不漏报。
3. **解释 WHY。** 每项不只给分，要说清"为什么是这个分"。
4. **区分增速放缓 vs 绝对下修。** R1 只有**砍绝对额**才算 🔴，单纯增速放缓最多 🟡——这是最容易误判的一项。
5. **低频项别瞎编。** 非财报季无新数据就老实沿用上期，不要为了"有变化"而强行改分。
6. **连续追踪。** 每期回看上期，总账不覆盖历史——这套工具的价值在时间序列。
7. **不是择时信号。** 输出的是"风险温度计"——最终仓位决策由用户自行判断。
