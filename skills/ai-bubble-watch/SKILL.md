# AI 泡沫破裂仪表盘（周度打分）

## 定位

回答一个问题：**这周，AI 资本周期（融资侧 + 需求侧）的压力比上周更高还是更低了？**

把 8 个**先行指标**量化成一个可跟踪的压力分数，用于持续观察 AI 资本开支链条的紧张程度。
它不是泡沫破裂概率，不预测"还有多久破裂"，也不替代你对仓位的独立判断。

> ⚠️ 核心理念：**动量 > 绝对值。** 单周指数从 20 跳到 40，比一直停在 50 更值得警惕。
> 真正的扳机是"第一家大厂砍 capex"或"OpenAI 募资翻车"——这两个亮红灯，无视总分直接升级等级。
> ⚠️ **动量陷阱**：指数上行可能来自（a）新指标扩容（如 2026-06-27 加入 Y4 当周 +8 含结构性抬升）；（b）同一事件在多个指标重复计分（Meta 售算力同时影响 Y2/R4/Y3）；（c）新闻量自然增长。解读"连续上行"前必须先排除这三类虚假动量。

运行频率：**每周末一次**（周六/周日）。

## 打分标准（每项 0 / 1 / 2）

通用语义：**0 = 🟢 正常（无信号）｜1 = 🟡 预警（苗头/传闻/边际恶化）｜2 = 🔴 触发（确认）**

| 指标 | 0（🟢正常） | 1（🟡预警） | 2（🔴触发） |
|------|-----------|-----------|-----------|
| **R1** capex 指引 | 最近一季全部维持或上修 | 任一公司措辞转谨慎/暗示见顶/增速大幅放缓 | 任一公司明确**下修绝对额** capex 或削减 AI 支出 |
| **R2** 大模型融资 | 新一轮顺利/超额认购/估值上行 | 募资周期拉长/平轮传闻/领投方退出传闻 | 募不满 / 明确**下折(down round)** / 重要轮次推迟取消 |
| **R3** GPU 租赁价 | 新旧卡价格稳定或上行 | 上一代(A100/H100)环比跌 15–30% 或闲置率上升 | 断崖(环比 >30%) 或大面积闲置/退租 |
| **R4** AI 融资栈 | 各子通道平稳、发行顺畅 | 任一子通道：利差走阔/评级展望下调/发行需求偏弱/私募股权退出去风险化 | 任一子通道：**首例实质违约** / 重大发行失败 / SPV 重组 |
| **Y1** NVIDIA DC 环比 | 环比增长 >10% | 环比增长 0–10%（明显减速） | 环比零增长或下滑 |
| **Y2** Neocloud | 无异常 | 集中度风险被点名/小客户流失（须列反向证据，如既有长期合同） | 大客户取消缩减 / Neocloud 财务困境 |
| **Y3** 循环交易 | 无新增/平稳 | 被分析师点名讨论（属"潜在利益循环风险"） | 监管/审计关注，且坐实循环融资要件（见下） |

**置信度**：每项标注证据强度。若证据不足以判断 → 取保守分（倾向给 1 而非 0，"宁可多报"），并标「需进一步核实」。

> **📌 R4 子通道分类纪律（易错点）**：R4 覆盖整个 AI 数据中心融资栈，证据必须标注属于哪个子通道，**不可把单一子通道的动静等同于"AI 资本链最脆弱环节正在显性化"**：
> - **公开债（Hyperscaler）**：如 Amazon/Meta/微软公司债利差走阔、长端需求偏弱、需提供更高利差 → 属「发行需求偏弱/利差走阔」= 1（黄）。即使"整体仍超额认购、成功发行"，只要长端需求弱+利差上升，记 1；**不等于"发行遇冷接近失败"**。
> - **私募信贷 / SPV-ABS / 项目融资**：如数据中心租赁背书债、私募信贷基金、SPV 结构 → 利差走阔=1，实质违约/重组=2。
> - **股权退出**：如 Blackstone 抛售数据中心权益、搁置园区 → 属去风险化，记 1，不等同违约。
> - R4 = 2 要求**任一子通道**出现"首例实质违约 / 重大发行失败 / SPV 重组"。无此类事件则维持 1，但须承认方向性压力在累积。

> **📌 R3 GPU 价格可比性纪律（防假警报）**：主要监控对象须是**当期代 GPU（B200/GB200）**的同型号/同区域/同租期价格、平台利用率、预留实例折扣、交付等待时间、CoreWeave 等合同续签价、推理 token 单价×调用量组合。**不可只盯上一代 H100**：随着新品上线，旧卡租赁价下跌很大程度是技术迭代+供给放量，摩尔定律会天然压低旧卡价格，只盯 H100 会让 R3 长期误报。旧卡贬值计入 1 分需明确标注"含技术迭代成分"，置信度不得高于"中"。

> **📌 Y3 循环交易判定门槛（防过早定性）**：NVIDIA"算力换收入分成"可能兼具客户扶持/渠道补贴/风投/生态建设/vendor financing 多重属性，**不得直接定性为循环交易**。须同时出现以下要件才接近"循环融资"：①NVIDIA 投资该客户；②客户再用融资购买 NVIDIA 芯片；③NVIDIA 收入确认依赖被投资客户；④客户缺乏独立偿付能力；⑤相关交易未充分披露。仅"分析师点名讨论 Oracle/OpenAI 单租户集中度"= 1（潜在利益循环风险），不写"坐实/本质"。

## 计算与等级

```
加权分 = Σ(R 指标得分 × 2) + Σ(Y 指标得分 × 1)  （2026-06-27 起 Y 从3项扩至4项）
满分   = (2+2+2+2)×2 + (2+2+2+2)×1 = 24  （2026-06-27 起从22扩至24）
AI资本周期压力指数 = round(加权分 / 24 × 100)   # 0–100，越高代表融资/需求侧压力越大（非破裂概率）
ΔWoW = 本期指数 − 上期指数               # 从总账读上期

> **📌 边际变化算术纪律**：任何"若 X 升档，指数变 Y"的表述都必须套用权重——
> R 指标每 +1 分 ⇒ 加权分 +2 ⇒ 指数 +8.3；Y 指标每 +1 分 ⇒ 加权分 +1 ⇒ 指数 +4.2。
> 例：R1 由 0→1，指数 42→50（非 44）；Y1 由 0→1，指数 42→46。**不可把整数直接加到指数上。**
```

| 指数 | 等级 | 含义（压力状态，非破裂预测） |
|------|------|------|
| 0–15 | 🟢 绿灯·压力低 | 融资/需求侧无可见裂缝 |
| 16–35 | 🟡 黄灯·初现裂缝 | 裂缝浮现但未触发硬信号，收紧警戒 |
| 36–55 | 🟠 橙灯·压力显著 | 多项指标进入黄/红，单点故障可能引发链式反应 |
| 56–75 | 🔴 红灯·加速恶化 | 多个硬信号触发，资本周期压力危机 |
| 76–100 | ⬛ 深红·危机 | 融资链或需求侧出现系统性断裂迹象 |

> ⚠️ 等级是**压力观察刻度**，不是"该减仓/加仓"的指令。具体仓位由用户结合其他信息自行决定。

### 硬触发规则（覆盖总分）

> 这两条**优先于**上面的指数→等级映射，因为它们是最强的破裂信号：
1. **任一 R 指标 = 🔴(2) → 等级至少升到 🟠 橙灯**（即使总指数还低）。
2. **≥2 个 R 指标 = 🔴(2) → 直接 🔴 红灯**。
3. **ΔWoW ≥ +15（单周）→ 即使绝对值不高，也要在报告开头标「⚠️加速恶化」**，并把建议等级上调一档。

## 执行流程

### 第 1 步：抓取证据（脚本）

```powershell
# 全量 8 指标（R1-R4 + Y1-Y4）
python scripts/ai_bubble_scan.py

# 周中只快查高频项
python scripts/ai_bubble_scan.py --only R2,R3,R4,Y2

# 指定日期
python scripts/ai_bubble_scan.py --date 2026-06-27
```

输出：`scripts/_ai_bubble_scan/YYYY-MM-DD.json`（每指标的最近新闻证据）。

### 第 2 步：AI 逐项核查与打分

1. 读 `scripts/_ai_bubble_scan/YYYY-MM-DD.json`。
2. **逐项判断**，证据不足或需要时效性更强的数据时，用 `WebSearch` 现场补搜（尤其 R3 GPU 租赁价、R4 利差、R1/Y1 财报数据）。
3. **低频指标处理**：读总账上期分数。若本期非财报季且无新证据 → 沿用上期，标「(沿用)」。若财报季有新数据 → 重新打分。
4. 每项给 0/1/2 + 一句证据摘要 + 置信度。**必须列出支撑打分的具体新闻标题 + 原文 URL**（这些将填入报告「证据明细」节）。证据摘要写"潜在/方向性"而非"坐实"，避免绝对化措辞（如"不可辩驳"）。
5. 按公式算加权分、指数、ΔWoW（从总账读上期指数）。**自查边际算术**：若报告中出现"若 X 升档指数变 Y"，必须套用权重（R×2 / Y×1）验证，不可直接加整数。
6. **应用硬触发规则**，确定最终等级。
7. **分类与归因纪律**（最易出错处）：
   - **R4 必须按子通道标注**（公开债/私募信贷/SPV-ABS/股权退出），不把公开债利差走阔包装成"私募信贷裂痕"。
   - **R3 必须优先盯当期代 GPU（B200/GB200）**价格与利用率，旧 H100 贬值需标注"含技术迭代"。
   - **Y3 不得把"算力换收入分成"直接定性为循环交易**；仅"分析师点名"记 1（潜在），坐实需满足循环融资五要件。
   - **区分"评分变化"与"叙事恶化"**：指数 ΔWoW 的全部数值来源必须能逐指标归因；若某指标叙事恶化但未跨阈值，其对指数贡献为 0，报告中须显式说明，不得写成"指数因此上涨"。
   - **避免同一事件跨指标重复计分**：如 Meta 售算力同时影响 Y2/R4/Y3，应在主指标计分、其余指标仅作旁证引用，不重复加分。
   - **信源质量**：确认型结论优先用一手源（TrendForce、Micron/Apple 财报与官方表述、公司 SEC 文件、Reuters/Bloomberg 原始报道），二手聚合源（Qoo10/Moneywise 等）仅作旁证并降置信度。

**取数来源提示**（补搜时优先）：
- R1：各厂财报电话会 transcript、Reuters/Bloomberg/CNBC、SemiAnalysis
- R2：The Information、Bloomberg、Reuters、TechCrunch
- Y4：Al Jazeera、CNBC、IDC、TrendForce DRAM 报价、厂商官方公告
- R3：vast.ai / RunPod / SF Compute 报价、SemiAnalysis ClusterMAX
- R4：Bloomberg、FT、S&P/Moody's 评级动作
- Y1：NVIDIA 季报（约 2月底/5月底/8月底/11月底）
- Y2：CoreWeave/Nebius 财报与新闻、客户集中度报道
- Y3：FT、The Information、卖方 vendor-financing 专题、10-Q 附注

## 原则

1. **动量优先，但先排雷。** 报告突出 ΔWoW 和趋势，但解读"连续上行"前先排除三类虚假动量：①新指标扩容带来的结构性抬升（如 2026-06-27 加入 Y4）；②同一事件跨指标重复计分；③新闻量自然增长推高分数。
2. **宁可多报。** 边界模糊倾向给 1 不给 0；硬触发宁愿误报也不漏报。
3. **解释 WHY。** 每项不只给分，要说清"为什么是这个分"，并标注置信度与证据来源。
4. **区分增速放缓 vs 绝对下修。** R1 只有**砍绝对额**才算 🔴，单纯增速放缓最多 🟡——这是最容易误判的一项。
5. **低频项别瞎编。** 非财报季无新数据就老实沿用上期，不要为了"有变化"而强行改分。
6. **连续追踪。** 每期回看上期，总账不覆盖历史——这套工具的价值在时间序列。
7. **不是择时信号（强约束）。** 输出的是**压力温度计**，不是泡沫破裂概率，不预测时间，不构成仓位指令。任何"该减/加仓"的结论都必须删除，改为"可支持的客观陈述 / 不可支持的推论"二分。完成历史回测前，禁止自动仓位建议。
8. **指标定义不可混淆。** R4 覆盖整个融资栈，须按子通道（公开债/私募信贷/SPV-ABS/股权退出）标注，不可把公开债利差走阔包装成"私募信贷裂痕"；R3 须优先盯当期代 GPU，旧卡贬值标注"含技术迭代"；Y3 不可把"算力换收入分成"直接定性为循环交易。
9. **归因纪律。** 必须区分"评分变化"与"叙事恶化"，ΔWoW 逐指标归因；叙事恶化但未跨阈值的指标对指数贡献为 0，不得写成"指数因此上涨"。
10. **边际算术自检。** "若 X 升档指数变 Y"必须套用权重（R×2 / Y×1）验证，不可直接加整数（分母固定为 24，非 22）。
11. **信源质量分级。** 确认型结论优先一手源（TrendForce、Micron/Apple 财报与官方、SEC 文件、Reuters/Bloomberg 原文），二手聚合源仅作旁证并降置信度；避免"不可辩驳"等绝对化措辞。
