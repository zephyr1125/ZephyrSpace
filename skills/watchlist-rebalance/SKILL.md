# Watchlist 存量资金调仓

始终使用简体中文。默认工作区 `E:/ObsidianVaults/ZephyrSpace`，Finance 项目 `E:/Work/Python/Finance`。生成有完整扫描、持仓依据、资金来源和金额核算的方案；没有合规资金来源时，结论可以是“本次不调仓”。

## 用户已确认的规则

- **范围仅限A股和港股，美股完全排除**：读取三个池后先按市场筛选，仅保留A股（`.SH`/`.SZ`/`.BJ`，兼容明确的北交所标识）及港股（`.HK`），再进行后续流程。美股不拉行情、不评分、不核持仓、不做资金配对，也不因排除美股而询问美股账户、美元汇率或跨境转款。
- 买入仅限 `watchlist_strategic.json`、`watchlist_core.json`、`watchlist_growth.json` 中上述市场的公司，且至少低估一档。完整扫描范围内条目，不按市值、持仓或排名抽样。
- 卖出同时满足两个条件：实际持有的个股处于**高估三档**，且有**至少低估一档、质量与价格加权评分优于卖方的替代标的**确实需要资金。高估本身不触发卖出。用户后续明确：高质量的低估一档与一般质量但更深低估的公司都可比较，取代先前“至少低估二档”的限制。
- 分档金额是**累计目标持仓市值，单位为人民币**，不是每次追加金额，也不是累计买入成本。

| Watchlist 等级 | 低估一档 | 低估二档 | 低估三档 |
|---|---:|---:|---:|
| B_GROWTH 成长 | 10,000 | 20,000 | 30,000 |
| A_CORE 核心 | 20,000 | 40,000 | 60,000 |
| S_STRATEGIC 战略 | 40,000 | 80,000 | 120,000 |

- 新增需求 = `max(0, 当档目标市值 - 当前实际持仓市值)`。已有市值达到目标时不追加；超过目标也不构成独立卖出理由。
- 不引入外部资金、不融资。默认本次买入只能由本次符合条件的持仓卖出净额支付，不自动动用已有现金、货币基金或 ETF。用户以后明确指定可用存量现金时才纳入。
- 按需筹资，不默认清空高估股。基本面恶化、退出 Watchlist、止损或超仓均不得擅自添加为独立卖出规则；可单独列出需要用户审视的风险。

## 1. 对齐规则与数据来源

先读 [数据接入与价格规则](references/data-and-rules.md)。读取三个池及 `data/watchlist_meta.json`，以 Vault 为成员与估值参数真源。Finance 的同步副本不能覆盖 Vault。读取 Finance 当前价格带函数和分档金额页面，确认有无变化；若与上述用户确认规则冲突，说明冲突并询问，不静默改变资金策略。

支持 JSON 数组及 `entries` 包装。先过滤市场，再按带市场后缀的证券代码去重并保留来源；不同池同一代码的评级或估值冲突须列出，受影响证券不进入金额方案。A/H 股不是同一证券。NONE/out_of_scope 不作买入池；ARCHIVED 条目照样列入范围内覆盖清单，但标记状态，恢复有效跟踪前不列入正式买入方案。

## 2. 全量价格扫描

拉取三个池内全部A股和港股的最新未复权报价，记录各证券交易时间、抓取时间、市场、币种、来源及盘中/收盘/延迟状态。休市用最近已完成交易日价格，不能把抓取时间当报价时间；按当地交易日历判断是否新鲜。零值、非有限值、静态旧价、停牌旧价、无时点缓存和请求失败均不能假装为实时行情。失败逐一列出，保持 `成功 + 缺失/冲突 = 范围内去重后全量`。范围外条目只计排除数量，不列详情。

按 Finance 七档精确边界分类，同时输出目标价、确定性、机械买入价及区间上下界。估值缺失或失效标记“待复核”，不能填零或自行用券商目标价替代。候选买卖标的还须核对对应最新估值报告、财报覆盖期和重大事件；通过联网读取官方披露核实研究后变化。重大新信息尚未计入目标价时，只保留机械筛选结果，不将其视为确认的买卖机会，不自动开展完整三件套。

## 3. 读取并核对真实持仓

通过项目 `.env` 的配置只读访问 Google Sheets“核算”表，读取完整行与表头；凭证只在进程内使用，不输出密钥或提交账户原始数据。不要调用只返回 A 股名单的旧周报函数作为完整持仓。

保留代码、市场、账户（若有）、币种、剩余份额、可卖份额（若有）、市值和数据时间。区分持仓行、结清行和汇总行；同证券同账户的真实分笔求和，重复快照不能重复计入。缺失股数不能当零，无代码行、负数、状态冲突单独核查。Google 读取失败不等于空仓；覆盖不完整不能给出全组合调仓金额。

用最新行情 × 股数 × 汇率重估市值，并与表中市值核对，避免把万元当元、港币当人民币或将已换算金额重复换汇。不靠 `trackingStatus=HOLDING` 推断股数。只核A股和港股的持仓覆盖，不自动混入另一个账户或其他人的表。表中若有美股行，在证券识别阶段排除，不进入持仓统计或金额方案。

持仓不在三个池的仍须展示。若有有效估值证据可判断其卖出条件，否则标记“缺少可核实估值，不能作为本次筹资来源”，不能仅因不在池内就卖出。ETF/基金只作资产背景，本规则不处理其卖出。

## 4. 生成候选与资金配对

先列所有低估一至三档的新增/加仓需求；需求大于零且通过估值有效性检查的标的进入比较集合，低估一档同样可以触发筹资。

按 [统一评分规则](references/scoring.md) 和 `rules.json` 计算买卖双方相同口径的总分，使用公司分、管理层分与连续价格分。**按总分比较，不能先按低估档位排序，也不能只看双分。** 展示分项、权重、买卖方分差和权重敏感性。配置中未确认的权重须标为“建议初始参数”，不可说成用户已确认；有用户新偏好则更新配置并记录。

总分更高是替换的必要条件，还需解释相对估值空间、关键反证和与现持仓的风险重叠，并核实交易摩擦是否值得。总分相同不换；轻微领先不强行交易，可因费用、估值不确定性或集中风险放弃，并给出理由。档位目标是上限，不要求把所有候选都买满。估值可靠程度已进入价格基准公式，不再暗中混为公司质量分；重大估值问题作为有效性闸门处理。

只对确认更优且尚有资金缺口的买入候选配对卖出来源。卖出候选必须实际持有且 `P >= 1.2 × T`。买方按统一总分降序考虑，高估卖方优先考虑总分较低者；逐对验证买方总分严格高于该卖方，必要时因风险重叠和交易成本调整次序并解释。低估一档买方符合这些条件时，也可以单独触发卖出筹资。高估卖方的公司分或管理层分缺失时，先补齐可核实的最新报告分数，不能补零使其看起来更差。

无合格卖方、无更优替代、候选已满仓，或资金不能到达目标账户时，不强行调仓。所有买方竞争同一资金池，不得各自重复使用全部卖出所得。

## 5. 计算金额与股数

- 先算目标缺口，再核实相关市场/券商的最小买入单位、卖出规则、可卖余额、税费及换汇成本。不要把所有 A 股都当作同一手数规则。联网核实当前规则并引用来源。
- 买入股数向下取整，使含费用支出不超过目标缺口及已分配预算。卖出在满足交易规则前提下筹足这笔需求及费用，卖量不得超可卖份额。为目标买单向上凑卖量后的零头留在现金，不为了花完零头超配买方。
- 各账户、币种独立做资金表。核实人民币卖款是否能用于港股通，或是否有已确认的港币账户划转路径及到账时点；跨账户方案只能标注条件与顺序，不能列为即时可执行。
- 交易前和交易后的市值均用同一行情快照及汇率；卖方只减卖出市值，买方只加买入市值，费用从现金扣除。筹资金额不采用成本价或浮盈。
- 逐资金池验证 `期末现金 = 获准期初现金 + 卖出净收入 - 买入含费支出 >= 0`，并验证组合总市值加现金的变化只来自费用/换汇损耗，不凭空增加资金。默认获准期初现金为零。
- 费用、手数、汇率或可卖余额不明时，给可审阅的条件性金额上限及待补数据，不能标成可执行股数。可以用明确标注的费用估算做方案，不把零费用假设隐藏起来。
- 不依靠口算完成资金闭合。用 Python/表格核算；随附 `scripts/calculate.py` 负责价格分类、统一评分和目标缺口，不负责行情获取、完整买卖判断或订单执行。

## 6. 交付与复查

先给“建议调仓/不调仓/数据不足”的结论、总卖出净额、总买入含费金额和余额。随后提供：

1. 数据覆盖：三个池范围内各自条数、去重总数、范围外排除数量、报价成功/缺失数、持仓来源与时点、人民币/港币汇率和估值版本。
2. 全量扫描表：公司/代码/等级/现价与币种/报价时间/目标价/买入基准/七档分类/持仓市值/目标市值/缺口/异常。
3. 买卖方案表：动作、证券与账户、原持仓、股数、金额（原币及人民币）、费用、调仓后市值、双方质量分/价格分/总分/分差、理由及对应资金来源。区分观察候选与实际纳入方案的交易。
4. 资金闭合表和执行顺序：先卖出，确认到账及实际成交后重新检查买方档位、缺口和费用，再买入。报价越界或估值变化则重算。
5. 未采纳机会及理由，剩余风险、缺失数据与条件。无机会也要交付全量覆盖结果。

如需落盘，完整报告写入 `99-个人观察/调仓方案/YYYY-MM-DD-HHmm-Watchlist调仓.md`，局部敏感明细仅用于此私人方案，不写公开公司页。优先 Obsidian CLI；不可用时使用文件操作。相同时点避免覆盖旧版。未经要求不提交 Git，不修改三个池、Finance 配置或 Google 表，不运行 Watchlist 同步，不下单。

交付前复核：每笔买入均在有效池且至少低估一档；每笔卖出均高估三档且存在已配对、统一总分更高且确有缺口的买方；未超目标、未超可卖数量、未重复用款、分币种资金闭合；报价和持仓失败没有被当作零；缺口清单与总覆盖数一致。
