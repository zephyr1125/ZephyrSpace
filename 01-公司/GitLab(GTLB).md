## 2. 业务构成与利润引擎

### 2.1 商业模式
GitLab 是**订阅制 + 用量制**的"一体化 DevSecOps 平台"：Free（开源漏斗）→ Premium/Ultimate（seat 订阅）→ GitLab Duo/Duo Agent Platform（AI，seat+usage credits）→ **GitLab Flex**（2026-06，年承诺按 rate card 弹性分配平台席位+credits+usage）。部署形态：GitLab.com（SaaS）、Self-Managed（自托管）、Dedicated（单租户托管）。

### 2.2 增长结构（Q2 FY2027，2026-07-31）
| 业务 | 占比 | YoY | 备注 |
|---|---|---|---|
| 订阅（SaaS+自托管）| ~90% 营收 | +21% | Q2 $258.3M |
| SaaS | **34% 营收** | **+36%** | Dedicated ARR >$70M |
| Ultimate（安全/合规档）| **59% ARR** | ~+35% | 8/10 最大单含 Ultimate |
| Duo / DAP / Flex | 早期放量 | — | 消费 CRR $40M+→目标 $100M+；Flex 6 周 $20M+ |

### 2.3 利润引擎一句话
**平台整合 + 高切换成本 + agentic 治理闸门**——客户把整个 SDLC 与合规数据放在 GitLab 内，"AI 助手越普及 → 越需要平台治理/存储"（CEO 口径）。DBNR 117%（Q2 环比回升）、net new ARR +42%、>$100k 客户 1,571（+17%）、~50% Fortune 100。

## 4. 护城河（详见深度分析 C 维度）

- **切换成本高**（平台承载 SDLC+合规数据）；**数据/上下文（Orbit）随使用加深**；部署灵活 + LLM 中立 + 开源生态。
- **局限**：整体开发者渗透率远逊 GitHub（Stack Overflow 2025：GitHub 81.1% vs GitLab 35.6%）；CI/CD 仅第三（19%）；主竞争 Microsoft/GitHub（Copilot 5,000 万用户、usage-based 后 +60% QoQ）。
